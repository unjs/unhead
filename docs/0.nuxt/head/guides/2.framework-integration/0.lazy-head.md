This page is for framework authors. It lists what an integration does to use the [lazy head](/docs/vue/head/guides/core-concepts/lazy-head). The examples use Nuxt hook names.

Nuxt does not ship the lazy head. Nuxt owns its head integration, so this page describes no Nuxt option. A Nuxt module or a patch can add it with the steps below.

::note
The lazy head is experimental. Its API may change in a minor release.
::

The server side needs no change. The server keeps its head from `@unhead/vue/server`, and the client swaps its head for the lazy head.

## Create the lazy head

Create the head with `createHead()` from `@unhead/vue/lazy`. Push the app head as the default client head does. If the integration registers `TemplateParamsPlugin` on the client, pass it in `lazyPlugins`, so its code loads with the runtime.

```ts
import { createHead } from '@unhead/vue/lazy'
import { defineNuxtPlugin } from 'nuxt/app'
import appHead from '#build/app-head.mjs'

export default defineNuxtPlugin({
  name: 'head',
  enforce: 'pre',
  setup(nuxtApp) {
    const head = createHead({
      lazyPlugins: () => import('@unhead/vue/plugins').then(m => [m.TemplateParamsPlugin]),
    })
    head.push(appHead)
    nuxtApp.vueApp.use(head)

    // The server did not render this page's head, so load at once.
    if (!nuxtApp.payload.serverRendered)
      head.load()

    // Hydration has ended.
    nuxtApp.hook('app:suspense:resolve', () => {
      head.render()
    })

    // Block the load for each navigation after hydration.
    nuxtApp.hook('page:loading:start', () => {
      if (!nuxtApp.isHydrating)
        head.blockLoad()
    })
    nuxtApp.hook('page:loading:end', () => {
      if (!nuxtApp.isHydrating)
        head.render()
    })
  },
})
```

Call `head.render()` once hydration ends. Before that call, a hydrating component adds entries without a load.

If a page has no server render, call `head.load()`. In Nuxt, that is a page with `ssr: false`.

Pass `load: 'idle'` to apply client only values at idle, without a change. Read [the `load` option](/docs/vue/head/guides/core-concepts/lazy-head#the-load-option).

## Turn off prefetch hints

The lazy head loads its runtime through a dynamic import inside the `unhead` package. If the renderer adds prefetch hints for dynamic imports of the entry, the browser downloads the runtime at once. Remove those imports from the entry's prefetch list:

```ts
const UNHEAD_CHUNK_RE = /[\\/]unhead[\\/]dist[\\/]/

nuxt.hook('build:manifest', (manifest) => {
  for (const chunk of Object.values(manifest)) {
    if (chunk.isEntry)
      chunk.dynamicImports = chunk.dynamicImports?.filter(id => !UNHEAD_CHUNK_RE.test(id))
  }
})
```

## Block the load during navigation

Block the load when a navigation starts, and release it when the navigation ends. Use the framework's navigation start and end events. In Nuxt, these are `page:loading:start` and `page:loading:end`.

- Start the block before the next page runs `setup()`. Nuxt's `page:start` fires too late: it runs after the new page's `setup()`.
- Release the block on every path, including a failure or an error.
- If the router has no navigation hooks, nothing can block the load. In Nuxt, `page:loading:start` and `page:loading:end` fire only when the app uses the pages integration.

Keep an existing `dom:beforeRender` pause. It also blocks the load, so the head stays on the old page until the pause lifts.

Without a block, the first step of a navigation loads the runtime while the next page still loads.

## Modules that push head tags

A module entry that changes on a navigation loads the runtime, as any other entry does. A module that pushes the same input on every page loads nothing.

A client hook, such as a `tags:resolve` listener, runs only inside the runtime. It takes effect with the first change.

## Recover from a failed load

If the runtime chunk fails to load, the document keeps its current head. A browser may keep the failed import for the page, so a later change can fail too. Pass `onLoadError` to recover, for example with a full reload on the next navigation.

Nuxt's default chunk error mode does not cover this import. It reloads on the next navigation only when that navigation fails on a chunk error.

## Streaming

Use the lazy head only for responses that do not stream. It does not support streaming SSR.

## Check the integration

Compare each page with the same page and the default client head:

- Hydration must change no head element.
- The browser must not fetch the runtime chunk before the first head change.
- A navigation must block the load until it ends.
- After each navigation, the whole head must match the default client head.
- A page with no server render must show its head.
- In development, the console shows a [dev warning](/docs/vue/head/guides/core-concepts/lazy-head#dev-warning) for each client tag that waits for a change. Fix each one, or pass `load: 'idle'`.
