This page is for framework authors. It lists what an integration does to use [compiler mode](/docs/vue/head/guides/core-concepts/compiler-mode) and the [lazy head](/docs/vue/head/guides/core-concepts/lazy-head). The examples use Nuxt hook names. Nuxt owns its head integration, so this page describes no Nuxt option.

::note
Compiler mode and the lazy head are experimental. Their API may change in a minor release.
::

The two features are separate:

- **Compiler mode** changes the server: turn on `compile`, create a compiled server head, and push compiled tags for renderer input.
- **The lazy head** changes the client: create a lazy head, end hydration, load at once on a page with no server render, and block the load during navigation.

## Server: compiler mode

### Turn on `compile`

Pass `compile: true` to the Unhead bundler plugin of the app build:

```ts
import { Unhead } from '@unhead/vue/bundler'

addBuildPlugin(Unhead({ compile: true }))
```

The option compiles `useHead()` and `useSeoMeta()` calls in the server build. It compiles app code, including calls that import from `#imports` or `nuxt/app`. In `node_modules`, it compiles the runtime files of Nuxt modules, which are files under `dist/runtime/`. Other files in `node_modules` stay as written. The client build stays as written.

A Nuxt layer from npm, such as Docus or shadcn-docs-nuxt, ships its app files outside `dist/runtime/`. Its calls stay as written. To compile them, add the layer to `filter.include`:

```ts
addBuildPlugin(Unhead({
  compile: true,
  filter: { include: [/[\\/]node_modules[\\/]docus[\\/]/] },
}))
```

`compile` needs `@unhead/bundler` at the same version as `@unhead/vue`. An older `@unhead/bundler` ignores the option and gives no warning. To check, build the server without minification and search its chunks for an import from `@unhead/vue/compiled`.

Turn off `compile` for a build that streams the head. A streamable head cannot take compiled tags.

### Create the compiled server head

Create the head with `createHead()` from `@unhead/vue/compiled/server` for each request. It renders the same HTML as the server head from `@unhead/vue/server`, and runs the same hooks and plugins.

### Compile the static app head

The app head is usually a build constant that the server pushes on each request. Compile it at build time, and emit it as a module for the server build. The client pushes the app head as normal input.

An app head can hold keys that are not tags. Nuxt's `app.head` has top-level `charset` and `viewport` keys. `compileTags()` returns `Bail` for them. Convert them to the meta tags they stand for before you compile:

```ts
import { compileTags } from 'unhead/compiled'

interface AppHead {
  charset?: string
  viewport?: string
  meta?: Record<string, unknown>[]
  [key: string]: unknown
}

// `charset` and `viewport` are config keys, not tags. A meta tag that `meta` already holds wins.
function toTagInput({ charset, viewport, meta = [], ...head }: AppHead) {
  const tags = [...meta]
  if (charset && !tags.some(tag => tag.charset))
    tags.unshift({ charset })
  if (viewport && !tags.some(tag => tag.name === 'viewport'))
    tags.unshift({ name: 'viewport', content: viewport })
  return { ...head, meta: tags }
}

export function appHeadModule(appHead: AppHead): string {
  const input = toTagInput(appHead)
  const result = compileTags(input)
  // Input that cannot compile stays normal input. It renders the same tags.
  return `export default ${JSON.stringify(result._tag === 'Ok' ? result.tags : input)}`
}
```

### Push compiled tags for renderer input

A renderer often pushes input in each request, such as the preload links of a route. Normal input keeps the request off the fastest render path. So compile it once per route, and keep the compiled tags in a map on the renderer instance. Never keep that map at module scope.

```ts
import type { CompiledTags } from 'unhead/compiled'
import type { Link } from 'unhead/types'
import { compileTags } from 'unhead/compiled'

export function createRenderer() {
  // One map per renderer instance, never at module scope.
  const routeTags = new Map<string, CompiledTags>()

  function routeLinkTags(routeId: string, links: Link[]) {
    let compiledTags = routeTags.get(routeId)
    if (!compiledTags) {
      const result = compileTags({ link: links })
      if (result._tag !== 'Ok')
        return { link: links }
      routeTags.set(routeId, compiledTags = result.tags)
    }
    return compiledTags
  }

  return { routeLinkTags }
}

// In each request. `routeId` must decide `links` exactly.
head.push(renderer.routeLinkTags(routeId, links))
```

A hit returns the compiled tags of the first input for that route. It never reads the new input. So use a key that decides the input exactly, and never a key built from request data. If your app has many routes, bound the map.

A value that changes on every request can be a dynamic value, if its tag has a fixed identity. For a JSON payload, give the script an `id`:

```ts
import { compileTags, dynamicValue } from 'unhead/compiled'

// Compile once, at module scope. The input holds no request data.
const payload = compileTags({
  script: [{
    id: '__APP_DATA__',
    type: 'application/json',
    innerHTML: dynamicValue(0),
    tagPosition: 'bodyClose',
  }],
}, { dynamicValues: 1 })
if (payload._tag !== 'Ok')
  throw new Error(payload.reason)

// In each request.
head.push(payload.tags, { values: [serializedPayload] })
```

Put tag options such as `tagPosition` inside the input. Compiled tags pushed with entry options take the slower path.

### Hooks and plugins

A listener on a render hook sends the whole head to the v3 render path. The HTML stays the same, but the render is slower. `TemplateParamsPlugin` and `InferSeoMetaPlugin` run on the faster path.

A module that reads head entries on the server reads `entry.input`. The input of a compiled entry reads as the head input it came from.

### Change tags from a module

A module that changes the resolved tags, for example to add an `og:url` from the canonical link, declares a tag transform. A `tags:*` hook takes the head off the server memo. A transform keeps it.

```ts
import { withTagTransform } from 'unhead/plugins'

head.use(head => withTagTransform(head, {
  key: 'my-module:og-url',
  transform: (tags) => {
    const canonical = tags.find(tag => tag.tag === 'link' && tag.props.rel === 'canonical')
    return canonical && !tags.some(tag => tag.props.property === 'og:url')
      ? [...tags, { tag: 'meta', props: { property: 'og:url', content: canonical.props.href } }]
      : tags
  },
}))
```

- The transform must be pure. It reads only `tags` and its context, and returns new tags for the ones it changes.
- `cacheKey` returns anything else the output depends on. The server memo keys its output on it. Return `null` to keep the memo from holding the output.
- On the server memo, a dynamic value reaches the transform as a token. So a transform copies or drops text it did not make, and never tests it. The example above copies the canonical href. If a transform must test text, `cacheKey` returns `null`.
- The v3 runtime runs the transform as a `tags:afterResolve` hook, so the output is the same with compiler mode on or off, and on the client.

`InferSeoMetaPlugin` is a tag transform.

## Client: the lazy head

Create the head with `createLazyHead()`. If the integration registers `TemplateParamsPlugin` on the client, pass it in `lazyPlugins`, so its code loads with the runtime.

```ts
import { createLazyHead } from '@unhead/vue/lazy'
import { defineNuxtPlugin } from 'nuxt/app'
import appHead from '#build/app-head.mjs'

export default defineNuxtPlugin({
  name: 'head',
  enforce: 'pre',
  setup(nuxtApp) {
    const head = createLazyHead({
      lazyPlugins: () => import('unhead/plugins').then(m => [m.TemplateParamsPlugin]),
    })
    head.push(appHead)
    nuxtApp.vueApp.use(head)

    // The server did not render this page's head, so load at once.
    if (!nuxtApp.payload.serverRendered)
      head.load()

    // Hydration has ended.
    nuxtApp.hook('app:suspense:resolve', () => {
      head.render()
    })

    // Block the load for each navigation after hydration.
    nuxtApp.hook('page:loading:start', () => {
      if (!nuxtApp.isHydrating)
        head.blockLoad()
    })
    nuxtApp.hook('page:loading:end', () => {
      if (!nuxtApp.isHydrating)
        head.render()
    })
  },
})
```

Call `head.render()` once hydration ends. Before that call, a hydrating component adds entries without a load. After it, nothing loads until the head changes.

If a page has no server render, call `head.load()`. In Nuxt, that is a page with `ssr: false`.

### Turn off prefetch hints for the lazy chunk

The lazy head loads its runtime through a dynamic import inside the `unhead` package. If the renderer adds prefetch hints for dynamic imports of the entry, the browser downloads the runtime at once. Remove those imports from the entry's prefetch list:

```ts
const UNHEAD_CHUNK_RE = /[\\/]unhead[\\/]dist[\\/]/

nuxt.hook('build:manifest', (manifest) => {
  for (const chunk of Object.values(manifest)) {
    if (chunk.isEntry)
      chunk.dynamicImports = chunk.dynamicImports?.filter(id => !UNHEAD_CHUNK_RE.test(id))
  }
})
```

### Block the load during navigation

Block the load when a navigation starts, and release it when the navigation ends. Use the framework's navigation start and end events. In Nuxt, these are `page:loading:start` and `page:loading:end`.

- Start the load block before the next page runs `setup()`. Nuxt's `page:start` fires too late: it runs after the new page's `setup()`.
- Release the load block on every path, including a failure or an error.
- If the router has no navigation hooks, nothing can block the load. In Nuxt, `page:loading:start` and `page:loading:end` fire only when the app uses the pages integration.

Keep an existing `dom:beforeRender` pause. It also blocks the load, so the head stays on the old page until the pause lifts.

### Recover from a failed load

If the runtime chunk fails to load, the document keeps its current head. A browser may keep the failed import for the page, so a later change can fail too. Pass `onLoadError` to recover, for example with a full reload on the next navigation.

Nuxt's default chunk error mode does not cover this import. It reloads on the next navigation only when that navigation fails on a chunk error.

### Streaming

Use the lazy head only for responses that do not stream. It does not support streaming SSR.

## Check the integration

Compare each page with the same page without compiler mode and the lazy head:

- The server head must match byte for byte.
- Hydration must change no head element.
- The browser must not fetch the runtime chunk before a head change.
- A navigation must block the load until it ends.
- After the runtime loads, the head must match the head of the standard client head.
- A page with no server render must show its head.
