Compiler mode turns `useHead()` and `useSeoMeta()` calls into compiled tags at build time. Compiled tags hold the normalized tags of one call. The server renders compiled tags without normalizing them on each request. On the client, the [lazy head](/docs/vue/head/guides/core-concepts/lazy-head) renders compiled tags with a small compiled runtime.

A compiled call renders the same tags as the same call without compiler mode. A call that cannot compile stays as written and works as before.

::note
Compiler mode is experimental. Its options, entry points, and compiled tag format may change in a minor release.
::

Compiler mode is for Vue apps that render on the server with `@unhead/vue` and a Vite or webpack build. If you build a framework integration, read [Compiler Mode Integration](/docs/nuxt/head/guides/framework-integration/compiler-mode).

## Setup

Compiler mode needs three changes: the build option, the server head, and the client head. The examples follow the structure of the [Vue installation guide](/docs/vue/head/guides/get-started/installation).

### 1. Turn on `compile`

```ts [vite.config.ts]
import vue from '@vitejs/plugin-vue'
import { Unhead } from '@unhead/vue/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue(), Unhead({ compile: true })],
})
```

For webpack, call `Unhead({ compile: true }).webpack()` from `@unhead/vue/bundler`.

The production build compiles calls for the server and the client. The dev server does not compile, so every call stays as written in development.

### 2. Use the compiled server head

Import `createHead()` from `@unhead/vue/compiled/server`. It takes compiled tags and normal input, and it runs every hook and plugin.

```ts [src/entry-server.ts]
import { createHead } from '@unhead/vue/compiled/server'
import { renderToString } from 'vue/server-renderer'
import { createApp } from './main'

export async function render(url: string) {
  const { app, router } = createApp()
  const head = createHead()
  app.use(head)

  await router.push(url)
  await router.isReady()

  const html = await renderToString(app)
  return { html, head }
}
```

Import `transformHtmlTemplate()` from the same entry, and use it as before:

```ts [server.ts]
import { transformHtmlTemplate } from '@unhead/vue/compiled/server'

const rendered = await render(url)
const html = transformHtmlTemplate(
  rendered.head,
  template.replace('<!--app-html-->', rendered.html),
)
```

### 3. Use the lazy client head

Create the head with `createLazyHead()`, then call `acceptCompiledTags()` on it. `acceptCompiledTags()` lets the compiled runtime load when every entry holds compiled tags.

```ts [src/entry-client.ts]
import { acceptCompiledTags, createLazyHead } from '@unhead/vue/lazy'
import { createApp } from './main'

const { app, router } = createApp()
const head = createLazyHead()
acceptCompiledTags(head)
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  // Hydration has ended.
  head.render()
})
```

Call `acceptCompiledTags()` where you create the head. The first compiled call also calls it. But an idle load can start before the first compiled call, and that load picks the larger full runtime.

If the page is not server rendered, call `head.load()` after you create the head.

Some frameworks create a full runtime head themselves, for example vite-ssg. A full runtime head cannot take compiled tags, and a compiled call on it throws. So the build turns off compiler mode when it finds one of these:

- `vite-ssg` in the dependencies of the app's `package.json`.
- An app module that imports `vite-ssg`.
- An app module that imports `createHead()` from `@unhead/vue/server`, `@unhead/vue/client`, `unhead/server`, or `unhead/client`.

The build then compiles nothing and warns once. The warning names the file it found. If the build finds the module after other modules compiled, the build fails with an error that says what to do.

### 4. Check the result

Build the app and render a page. The head must match the head that the same page renders without compiler mode.

To see which calls compiled, build without minification. Compiled calls appear in the page chunks as `useCompiledHead()` and `useCompiledSeoMeta()`.

To see why the client loaded the full runtime, build once with `compile: { debug: true }`:

```ts [vite.config.ts]
Unhead({ compile: { debug: true } })
```

Then read `_fullRuntimeReason` on the head in the browser console. The debug build sets it only when the full runtime loads:

```js
// In a Nuxt app, use '#__nuxt'
const head = document.querySelector('#app').__vue_app__.config.globalProperties.$unhead
head._fullRuntimeReason
```

- `undefined`: the full runtime has not loaded.
- An entry: the first entry without compiled tags. Its `input` shows the call that stayed as written.
- `true`: every entry holds compiled tags. A hook, a render option, or a dynamic value loaded the full runtime.

A build without `debug` leaves out this code, so `_fullRuntimeReason` costs no bytes and stays `undefined`. The dev server compiles nothing, so check a production build.

## What compiles

The build compiles a call when it can prove the tags from the source code. Each part that can change at runtime becomes a dynamic value.

```vue [src/pages/Post.vue]
<script setup lang="ts">
import { useHead, useSeoMeta } from '@unhead/vue'
import { computed } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const title = computed(() => `Post ${route.params.slug}`)

// Compiles: `title` and the getter become dynamic values.
useHead({
  title,
  link: [{ rel: 'canonical', href: () => `https://example.com${route.path}` }],
})

// Compiles: `useSeoMeta()` is a statement on its own.
useSeoMeta({
  description: () => `Read the post ${route.params.slug}`,
  ogType: 'article',
})
</script>
```

A call compiles when all of these are true:

- It calls `useHead()`, `useServerHead()`, `useSeoMeta()`, or `useServerSeoMeta()` from `@unhead/vue`, `#imports`, `nuxt/app`, or an auto import.
- The input is an object literal. Its keys and tag lists are written out, with no spread. The input can also be a `const` that holds an object literal, if the call is the only code that reads it.
- A `useHead()` input can also be a getter, such as `useHead(() => ({ title: post.value.title }))`. The getter takes no parameters, and its last statement returns an object literal that follows the rule above. Each value of that object becomes a dynamic value, and the getter runs once for all of them.
- The only option is `head`.
- A `useSeoMeta()` call is a statement on its own. Its return value is not used.

These calls stay as written:

| Call | Why it stays |
| --- | --- |
| `useHead(postHead)` | The input is a variable that other code reads, or that is not a `const` object literal. |
| `useHead({ titleTemplate: t => \`${t} - Site\` })` | `titleTemplate` is a function. The build warns. Use a string, such as `'%s %separator %siteName'`. |
| `useHead({ ...base, title: 'Post' })` | The input has a spread. |
| `useHead({ meta: tags })` | The tag list is a variable. |
| `useHead({ title: 'Post' }, { tagPriority: 'high' })` | It has an option other than `head`. |
| `useHead({ script: [{ src: '/a.js', onload }] })` | It has an event handler. |
| `const entry = useSeoMeta({ description })` | It uses the return value of `useSeoMeta()`. |
| `useHead(() => canonical ? { link } : {})` | The getter can return objects of different shapes. Call `useHead()` only when `canonical` is set, or return the same keys from each branch. |
| `useHead(() => { if (!post) return {}; return { title } })` | The getter returns in more than one place. |
| `useSeoMeta(() => ({ title }))` | Without compiler mode, `useSeoMeta()` renders nothing for a getter, so the call stays the same. |

The build leaves calls in CommonJS files as written. In `node_modules`, the build compiles only the runtime files of Nuxt modules, which are files under `dist/runtime/`. To compile another dependency, add it to `filter.include`:

```ts [vite.config.ts]
Unhead({
  compile: true,
  // Compiles the source files of a Nuxt layer from npm
  filter: { include: [/[\\/]node_modules[\\/]docus[\\/]/] },
})
```

## Dynamic values

A dynamic value is an expression in a compiled call that the build cannot know. The call evaluates each dynamic value once, where it stands, as it does without compiler mode.

- A ref, computed ref, or getter stays reactive. On the client, one effect tracks every dynamic value of a call.
- On the server, a ref, computed ref, or getter resolves once, at the first render.
- A plain value does not update, as without compiler mode.

A dynamic value cannot decide which tags exist or how they merge. If a call has a dynamic value in one of these places, the whole call stays as written:

| Place | Examples |
| --- | --- |
| Tag identity and order | `key`, `id`, `tagPriority`, `tagPosition`, `tagDuplicateStrategy`, `processTemplateParams` |
| Merged attributes | `class` and `style` |
| Meta identity | `name`, `property`, `http-equiv`, and `charset` |
| Link identity | `rel`, `hreflang`, `as`, and `type`. Also `href` when it identifies the link. The `href` of a canonical link, or of a link with a `key` or `id`, can be a dynamic value. |
| Script identity | `type`, `src`, `async`, and `defer`. Also inline content, unless the script has an `id` or `key`. |
| Whole tags | Any dynamic value in `titleTemplate` or `templateParams` |
| Style tags | A style attribute. Style content, unless the style has an `id` or `key` and its content comes before its attributes. |
| Packed `useSeoMeta()` keys | A dynamic value inside the object or list of a key such as `ogImage`, `articleTag`, or `robots`, when the build cannot prove the tags for each string value. A list with written out items, such as `ogImage: [{ url: image, width: 1200 }]`, usually compiles. A dynamic value for the whole key can compile. |

Every dynamic value renders the same tags as without compiler mode. On the client, these values stay on the compiled runtime:

- In `useHead()`: a string, a finite number, `true`, `false`, `null`, or `undefined`.
- In `useSeoMeta()`: a string other than `''` and `'true'`, a finite number, or `undefined`. An `undefined` value removes its tags, as without compiler mode.

Other values load the full runtime. These are a list, an object, a number that is not finite, and in `useSeoMeta()`, `''`, `'true'`, `null`, or a boolean. A number in a `useSeoMeta()` list of strings, such as `articleTag`, and `undefined` in an item of a list also load it. A style content value that holds `@import` also loads it. On the server, a value other than a string or a number other than `0` takes a slower path with the same output. So do `''` and `'true'`.

Data that loads after the first render often starts as `undefined`, as in `title: () => data.value?.title`. Until the data loads, the head leaves out that tag, as without compiler mode.

## Which runtime the client loads

The lazy head has two runtimes. The compiled runtime renders compiled tags only. The full runtime is the standard Unhead DOM renderer.

The compiled runtime loads when every entry holds compiled tags. The full runtime loads in these cases:

- An entry holds no compiled tags. Examples: a call that stayed as written, `useScript()`, or a `<Head>` component.
- A dynamic value needs the full runtime.
- A hook has a listener other than `TemplateParamsPlugin`, `InferSeoMetaPlugin`, `dom:beforeRender`, or `dom:rendered`.
- The head has a custom `render` option.

The compiled runtime hands over to the full runtime when a page needs it. The output stays the same.

## Strict head

`createHead()` from `@unhead/vue/compiled/server-strict` creates a strict head. A strict head renders compiled tags only. It has no normal input path, no hooks, and no full runtime.

```ts [src/entry-server.ts]
import { createHead, templateParams } from '@unhead/vue/compiled/server-strict'

const head = createHead({ plugins: [templateParams] })
```

A strict head throws on input it cannot render:

- A call that did not compile.
- A hook.
- A plugin other than its `templateParams` export.
- An entry option, such as `tagPriority`.

Use it only when every head call on the server compiles. Every dynamic value must also be a string or a finite number.

`transformHtmlTemplate()` pushes the head tags of the HTML template as normal input, so a strict head throws. Use `transformHtmlTemplateRaw()` from `unhead/compiled/server` instead. It leaves the template's own head tags where they are.

## Known limitations

Check these before you ship compiler mode or the lazy head. Each row says what you see and what to do instead.

### Client

| Situation | What happens | What to do |
| --- | --- | --- |
| `useHead()` in `onBeforeMount()` of a hydrating component, behind `import.meta.client` or `process.client` in `setup()`, or in a `.client` plugin | The tag reaches the document at browser idle. | Call it in `setup()` on both sides, or in `onMounted()`. In a plugin, call `head.load()` after the call. |
| Streaming SSR | The lazy head does not support streaming. | Keep `compile` off, and use `createStreamableHead()`. |
| The runtime chunk fails to load | The document keeps its current head. A browser may keep the failed `import()` for the page, so a retry can fail too. | Use `onLoadError` to recover, for example with a full reload on the next navigation. |
| A navigation | An idle load or a head change can start the download while the next page loads. A router with no navigation hooks cannot block the load. | [Block the load](/docs/vue/head/guides/core-concepts/lazy-head#block-the-load-during-navigation) when each navigation starts, and release it when it ends. |
| A read of `entry.input`, or `resolveTags(head)`, before the full runtime loads | The `input` of a compiled entry is its compiled tags. `resolveTags(head)` returns no tags for it. | Read the tags on the server, or from the document. |
| A second document | The compiled runtime renders only into the document of its head. | Create a separate lazy head for each document. |
| A dynamic value that is a list or an object, or a `useSeoMeta()` value of `''`, `'true'`, `null`, or a boolean | The head moves to the full runtime. The output is correct, but the page loads more JS. | Pass a string, a number, or `undefined`. For a list, write out its items. [Dynamic values](#dynamic-values) lists each case. |
| A `titleTemplate` function, often in `app.vue` | The call stays as written, and every page loads the full runtime. The build warns. | Use a string template with template params, such as `'%s %separator %siteName'`. |
| `InferSeoMetaPlugin` registered before `acceptCompiledTags()` | The plugin pushes normal input, so the page loads the full runtime. | Call `acceptCompiledTags()` where you create the head, before any plugin. |
| Entries that changed during hydration, on the full runtime | Adoption and the next render both write `document.title`. | No action. The final title is correct. |
| A title that hydration pushed and then disposed, on the full runtime, with no server title | An empty `<title>` element stays in the document. | Render the title on the server too. |

### Server

| Situation | What happens | What to do |
| --- | --- | --- |
| An in-place edit of `entry.input` of a compiled server entry | The edit never reaches the HTML. | Call `patch()` on the entry that `push()` returned. |
| A spread, `Object.keys()`, or `JSON.stringify()` of a compiled server entry | The copy has no `input`, because `input` is a getter. | Read `entry.input` directly. |
| A strict head | Entries expose no `input`. `transformHtmlTemplate()` throws. A render can leave `head._title` and `head._templateParams` unset. | Use `transformHtmlTemplateRaw()`. If your code reads entry input, the title, or template params, use the compiled server head. |
| Compiled tags created per request | After 2,048 new sets of compiled tags in one process, the render memo resets. After four resets it stays off. The output stays correct, but each render is slower. | Create compiled tags once: at build time, at module scope, or in a map on your renderer. |
| A loose tag with a `before:` or `after:` priority, with Nuxt 4 legacy plugins | The Promises hook checks loose entries twice in that render. The HTML is the same. | Use a number, `high`, or `low` instead. |

### Build

| Situation | What happens | What to do |
| --- | --- | --- |
| An import cycle that runs `setup()` while modules evaluate | Compiled tags are a module-scope constant. The call can reach them before they exist, and throws a `ReferenceError`. | Break the import cycle. |
| Calls that stay as written | They run on the full runtime. This covers dynamic structure, the `<Head>` component, Nuxt's `<Head>`, `<Title>`, and `<Meta>` components, and `useScript()`. | Write static input where you can. [What compiles](#what-compiles) lists the rules. |
| A dependency in `node_modules` outside `dist/runtime/`, such as a Nuxt layer from npm | Its calls stay as written. | Add the dependency to `filter.include`. |
| A head that the app or a framework creates with `createHead()` from `@unhead/vue/client` or `@unhead/vue/server`, as vite-ssg does | The build turns off compiler mode and warns once. It names the file. If other modules compiled first, the build fails. | Create the heads with `@unhead/vue/lazy` and `@unhead/vue/compiled/server`, or set `compile: false`. |
| A dependency other than vite-ssg that creates a full runtime head | The build cannot see it. Each compiled call throws, and the error says what to do. | Create the heads with `@unhead/vue/lazy` and `@unhead/vue/compiled/server`, or set `compile: false`. |
