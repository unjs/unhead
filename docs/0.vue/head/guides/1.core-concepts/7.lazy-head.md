On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

Your head calls stay as written. `useHead()`, `useSeoMeta()`, and `useScript()` work as before. No build step is needed.

Keep `createHead()` from `@unhead/vue/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/vue/head/guides/core-concepts/streaming). The lazy head does not support streaming.

## Setup

Replace `createHead()` in the client entry with the one from `@unhead/vue/lazy`:

```ts [src/entry-client.ts]
import { createHead } from '@unhead/vue/lazy'
import { createApp } from './main'

const { app, router } = createApp()
const head = createHead()
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  // Hydration has ended.
  head.render()

  // Block the load while a navigation runs.
  router.beforeEach(() => {
    head.blockLoad()
  })
  // Release it when the navigation ends, even if it failed.
  router.afterEach(() => {
    head.render()
  })
  router.onError(() => {
    head.render()
  })
})
```

Call `head.render()` once hydration ends. Before that call, a `useHead()` call in a hydrating component adds an entry and loads nothing. Add the navigation guards after that call, because `blockLoad()` also marks the end of hydration.

The server keeps `createHead()` from `@unhead/vue/server`. Nothing changes there.

## What a change does

After hydration, the first head change loads the runtime. The runtime renders the whole head, and it handles every later change. A patch with the same input as before is no change.

Most navigations change the head, so the runtime usually loads on the first navigation. The lazy head saves bytes before the first paint and until that navigation.

Crawler tags, such as `og:` meta tags and JSON-LD, also wait for the first change. The `serverOnlyCrawlerTags` option of the bundler plugin drops them from the client bundle. That option ships apart from the lazy head.

## The `load` option

`load` decides when the runtime loads on a server rendered page:

| Value | When the runtime loads |
| --- | --- |
| `'change'` | On the first head change. The default. |
| `'idle'` | At browser idle after hydration, even with no change. |

```ts
const head = createHead({ load: 'idle' })
```

With `'change'`, a value that the client computes differently from the server waits for the first change. With `'idle'`, the runtime applies such values at idle, as the default client head applies them at hydration. `'idle'` loads the runtime on every page, so it saves bytes before the first paint, not by idle.

These also load the runtime, with either value:

| Trigger | When the runtime loads |
| --- | --- |
| A call the server never ran | At once. Examples: `useHead()` in `onMounted()`, or in a component that mounts after hydration. |
| A patch or dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When it adds its script to the document. |
| `head.load()` | At once. |

A patch with the same input as before loads nothing. A reactive input resolves again when the router sets the route during hydration, and that patch changes nothing.

If a page is not server rendered, call `head.load()` after you create the head. `head.load()` is safe to call more than once. It resolves `false` if the chunk fails to load. The `onLoadError` option receives the error, and a later change or `head.load()` tries again.

## Block the load during navigation

A change can start the load while the next page still loads. `head.blockLoad()` blocks the load until the next `head.render()`. If entries changed during the block, the runtime loads when the block ends. A direct `head.load()` still runs during a block.

The [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause also blocks the load. Call `head.render()` after you lift the pause, as the [Pause DOM Rendering](/docs/vue/head/guides/core-concepts/pausing-dom-rendering) guide shows.

## Plugins and template params

Plugin setup runs when you create the head. Plugin hooks take effect when the runtime loads.

To keep plugin code out of the eager chunk, pass a loader to `lazyPlugins`. It runs when the runtime loads:

```ts
const head = createHead({
  lazyPlugins: () => import('@unhead/vue/plugins').then(m => [m.TemplateParamsPlugin]),
})
```

## Dev warning

With `load: 'change'`, a tag that the client renders differently from the server waits for the first change. In development, the lazy head checks for this after hydration. It resolves the tags the client would render and compares them with the server head in the document. The check changes nothing in the document.

The console shows one warning for each tag and the component that pushed it. The lazy head keeps a list of warned tags for the browser tab, so a tag that differs on every page warns once:

```txt
[unhead] <meta name="theme-color"> differs from the server head in content. Pushed by components/ColorMode.vue. It applies on the first head change. Push the same input on the server and the client, set load: 'idle', or call head.load().
```

The check compares the title, the `meta`, `link`, `script`, `style`, and `noscript` tags, and the html and body attributes. It stays silent for a tag that the server rendered and the client does not push. It does not run with `load: 'idle'`. A production build holds no code for it.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| Streaming SSR | The lazy head does not support streaming. | Keep `createHead()` from `@unhead/vue/client`. |
| A value that the client computes differently from the server, for example one that reads `import.meta.server` or the color mode | With `load: 'change'`, the document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, set `load: 'idle'`, or call `head.load()` after hydration. |
| `useHead()` in `onBeforeMount()` of a hydrating component, behind `import.meta.client` in `setup()`, or in a client only plugin | The head counts the call as server rendered, so the tag waits for a change. | Call it in `setup()` on both sides, or in `onMounted()`. In a plugin, call `head.load()` after the call. |
| The runtime chunk fails to load | The document keeps its current head. A browser may keep the failed `import()` for the page, so a retry can fail too. | Use `onLoadError` to recover, for example with a full reload on the next navigation. |
| A router with no navigation hooks | Nothing can block the load, so it can start while the next page loads. | Call `head.blockLoad()` and `head.render()` from your own navigation code. |
