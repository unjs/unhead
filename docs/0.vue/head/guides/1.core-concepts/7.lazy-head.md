On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

This guide is for the code that owns the client entry: a framework integration or a custom Vite SSR setup. Components need no change. `useHead()`, `useSeoMeta()`, and `useScript()` work as before. No build step is needed.

Nuxt does not ship the lazy head yet. In a Nuxt app, Nuxt creates the head, so read [Lazy Head Integration](/docs/nuxt/head/guides/framework-integration/lazy-head) instead.

## What the client entry provides

The lazy head does not replace the client head on its own. It needs three signals that only the client entry has:

| Signal | Call | If the call is missing |
| --- | --- | --- |
| Hydration ended | `head.render()` | A push outside a component, such as from a plugin, counts as server rendered, so its tags wait for a change. The dev warning never runs. |
| A navigation runs | A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause, then `head.render()` when it ends | The runtime loads while the next page still loads. |
| No server head applies | `head.load()` right after you create the head | The first entries count as server rendered, so their tags wait for a change. A page with no server render shows no head until then. |

Keep `createHead()` from `@unhead/vue/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/vue/head/guides/core-concepts/streaming). The lazy head does not support streaming.

## Setup

Replace `createHead()` in the client entry with the one from `@unhead/vue/lazy`:

```ts [src/entry-client.ts]
import { createHead } from '@unhead/vue/lazy'
import { nextTick } from 'vue'
import { createApp } from './main'

const { app, router } = createApp()
const head = createHead()
// Pause head updates while a navigation runs. The pause also holds the load.
let navigating = false
head.hooks.hook('dom:beforeRender', (ctx) => {
  if (navigating)
    ctx.shouldRender = false
})
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  // Hydration has ended.
  head.render()

  router.beforeEach(() => {
    navigating = true
  })
  // Lift the pause after the new page renders, and when the navigation fails.
  const done = () => {
    navigating = false
    head.render()
  }
  router.afterEach(() => nextTick(done))
  router.onError(done)
})
```

Call `head.render()` once hydration ends. Before that call, a `useHead()` call in a hydrating component adds an entry and loads nothing.

Vue Router calls `afterEach` before the new page renders. So lift the pause in `nextTick()`, after the old page removes its entries and the new page adds its entries. A page that renders later, such as an async `setup()` inside `<Suspense>`, needs a later release. For such a page, lift the pause when `<Suspense>` resolves.

Without the pause, the first step of a navigation loads the runtime while the next page still loads. The [Pause DOM Rendering](/docs/vue/head/guides/core-concepts/pausing-dom-rendering) guide shows the same pause for the default client head.

The server keeps `createHead()` from `@unhead/vue/server`. Nothing changes there.

## What a change does

After hydration, the first head change loads the runtime. The runtime renders the whole head, and it handles every later change. A patch with the same input as before is no change.

Most navigations change the head, so the runtime usually loads on the first navigation. The lazy head saves bytes before the first paint and until that navigation.

Crawler tags, such as `og:` meta tags and JSON-LD, also wait for the first change. The `serverOnlyCrawlerTags` option of the bundler plugin drops them from the client bundle. That option ships apart from the lazy head.

## What else loads the runtime

A value that the client computes differently from the server waits for the first change. These also load the runtime:

| Trigger | When the runtime loads |
| --- | --- |
| A call the server never ran | At once. Examples: `useHead()` in `onMounted()`, or in a component that mounts after hydration. |
| A patch or dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When it adds its script to the document. |
| `head.load()` | At once. Call it at idle to apply client only values without a change. |

A patch with the same input as before loads nothing. A reactive input resolves again when the router sets the route during hydration, and that patch changes nothing.

The lazy head compares plain objects, lists, and primitive values. It cannot read the value of a getter function or of another object, such as a promise. So a patch that holds one of these loads the runtime. A `titleTemplate` function and an event handler, such as `onload`, compare by reference.

If a page is not server rendered, or you create the head after hydration ended, call `head.load()` after you create the head. Otherwise the head counts the first entries as server rendered, and they wait for a change. A load that no change started before hydration ends tells the head that no server head applies, so it adopts nothing. `head.load()` is safe to call more than once. It resolves `false` if the chunk fails to load. The `onLoadError` option receives the error, and a later change or `head.load()` tries again.

A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause holds the load. Call `head.render()` after you lift the pause. If entries changed during the pause, the runtime loads then. A direct `head.load()` still loads during a pause, and its first render waits for the pause to lift.

## Plugins and template params

Plugin setup runs when you create the head. Most plugin hooks take effect when the runtime loads. Some hooks run before the load. `entries:updated` runs on each push and dispose, and on each patch that changes the input. A patch with the same input as before does not run it. `dom:beforeRender` runs when a change checks for a pause. In development, the dev check also runs the resolve hooks, such as `tags:resolve`, once after hydration. Read [Modules that push head tags](/docs/nuxt/head/guides/framework-integration/lazy-head#modules-that-push-head-tags) for the details.

To keep plugin code out of the eager chunk, pass a loader to `lazyPlugins`. It runs when the runtime loads. In development, it also runs after hydration for the dev check:

```ts
const head = createHead({
  lazyPlugins: () => import('@unhead/vue/plugins').then(m => [m.TemplateParamsPlugin]),
})
```

## Dev warning

A tag that the client renders differently from the server waits for the first change. In development, the lazy head checks for this after hydration. It resolves the tags the client would render and compares them with the server head in the document. The check changes nothing in the document.

The console shows one warning for each tag and the component that pushed it. The lazy head keeps a list of warned tags for the browser tab, so a tag that differs on every page warns once:

```txt
[unhead] <meta name="theme-color"> differs from the server head in content. Pushed by components/ColorMode.vue. It applies on the first head change. Push the same input on the server and the client, or call head.load().
```

The check compares the title, the `meta`, `link`, `script`, `style`, and `noscript` tags, and the html and body attributes. It stays silent for a tag that the server rendered and the client does not push. It does not run if the runtime already loads. A production build holds no code for it.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| Streaming SSR | The lazy head does not support streaming. | Keep `createHead()` from `@unhead/vue/client`. |
| A value that the client computes differently from the server, for example one that reads `import.meta.server` or the color mode | The document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, or call `head.load()` after hydration. |
| `useHead()` in `onBeforeMount()` of a hydrating component, behind `import.meta.client` in `setup()`, or in a client only plugin | The head counts the call as server rendered, so the tag waits for a change. | Call it in `setup()` on both sides, or in `onMounted()`. In a plugin, call `head.load()` after the call. |
| The runtime chunk fails to load | The document keeps its current head. A browser may keep the failed `import()` for the page, so a retry can fail too. | Use `onLoadError` to recover, for example with a full reload on the next navigation. |
| A router with no navigation hooks | Nothing pauses the load, so it can start while the next page loads. | Pause with a `dom:beforeRender` hook from your own navigation code, and call `head.render()` when the navigation ends. |
