On a server rendered page, the server already wrote the right head tags. `createLazyHead()` from `@unhead/vue/lazy` keeps head entries in memory and leaves those tags alone. The standard DOM runtime loads from a separate chunk, only when the head changes. A page that never changes its head never loads it.

::note
The lazy head is experimental. Its API may change in a minor release.
::

Use the lazy head when the server renders the head of every page. Keep `createHead()` from `@unhead/vue/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/vue/head/guides/core-concepts/streaming). The lazy head does not support streaming.

## Setup

Replace `createHead()` in the client entry. The server entry does not change, and `useHead()` works as before.

```ts [src/entry-client.ts]
import { createLazyHead } from '@unhead/vue/lazy'
import { createApp } from './main'

const { app, router } = createApp()
const head = createLazyHead()
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  // Hydration has ended.
  head.render()
})
```

Call `head.render()` once hydration ends. Before that call, a `useHead()` call in a hydrating component adds an entry and loads nothing. After that call, a head change loads the runtime, unless a [load block](#block-the-load-during-navigation) or a [pause](#pause-dom-updates) blocks it.

After hydration, the document still holds the server tags. The browser fetches no runtime chunk.

## When the runtime loads

| Trigger | When the runtime loads |
| --- | --- |
| A change after hydration | At once. Examples: a ref in `useHead()` changes, or a new page calls `useHead()`. |
| A call the server never ran | At once. Examples: `useHead()` in `onMounted()`, or in a component that mounts after hydration. |
| A patch or dispose during hydration | At once, because the client already differs from the server. |
| `head.load()` | At once. |
| `useScript()` | When its trigger adds the script to the document. |

The runtime does not load at browser idle. Until a change, nothing loads and nothing runs.

Once loaded, the head renders each change, as the standard client head does. It first adopts the server tags, so it updates them in place.

If a page is not server rendered, call `head.load()` after you create the head:

```ts
await head.load()
```

`head.load()` is safe to call more than once. It resolves `false` if the chunk fails to load. The `onLoadError` option receives the error, and a later change or `head.load()` tries again.

## Block the load during navigation

A head change can start the load while the next page still loads. Call `head.blockLoad()` when a navigation starts, and `head.render()` when it ends:

```ts [src/entry-client.ts]
router.isReady().then(() => {
  app.mount('#app')
  head.render()

  // Block the load while a navigation runs.
  router.beforeEach(() => {
    head.blockLoad()
  })
  // Release it when the navigation ends, even if it failed.
  router.afterEach(() => {
    head.render()
  })
  router.onError(() => {
    head.render()
  })
})
```

`blockLoad()` blocks changes. `head.render()` releases the load block. If entries changed during the load block, the runtime loads at once. If nothing changed, nothing loads. A direct `head.load()` still runs during a load block.

Add the guards after `head.render()`. `blockLoad()` also marks the end of hydration, so a load block during the first navigation ends hydration too early.

## Pause DOM updates

The [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause also blocks the load. While a hook sets `shouldRender` to `false`, changes after hydration wait. Call `head.render()` after you lift the pause, as the [Pause DOM Rendering](/docs/vue/head/guides/core-concepts/pausing-dom-rendering) guide shows.

A patch or dispose during hydration still loads the runtime while paused. The runtime then writes nothing to the document until the pause lifts.

## Plugins and template params

Plugin setup runs when you create the head. Plugin hooks take effect when the runtime loads.

To keep plugin code out of the eager chunk, pass a loader to `lazyPlugins`. It runs when the runtime loads:

```ts
const head = createLazyHead({
  lazyPlugins: () => import('./head-plugins').then(m => [m.analyticsPlugin]),
})
```

`TemplateParamsPlugin` works in `plugins`, as on the client head. To keep its code out of the eager chunk, pass it through `lazyPlugins` instead:

```ts
const head = createLazyHead({
  lazyPlugins: () => import('unhead/plugins').then(m => [m.TemplateParamsPlugin]),
})
```

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| `useHead()` in `onBeforeMount()` of a hydrating component, behind `import.meta.client` or `process.client` in `setup()`, or in a `.client` plugin | The head counts the call as server rendered, so the tag does not reach the document until the next change. | Call it in `setup()` on both sides, or in `onMounted()`. In a plugin, call `head.load()` after the call. |
| The runtime chunk fails to load | The document keeps its current head. A browser may keep the failed `import()` for the page, so a retry can fail too. | Use `onLoadError` to recover, for example with a full reload on the next navigation. |
| A router with no navigation hooks | Nothing can block the load, so it can start while the next page loads. | Call `head.blockLoad()` and `head.render()` from your own navigation code. |
| A title that hydration pushed and then disposed, with no server title | An empty `<title>` element stays in the document. | Render the title on the server too. |
