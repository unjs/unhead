The lazy head queues client entries while the server tags stay in the document. Your app or framework calls `head.load()` when it needs to apply the queued entries.

::note
The lazy head is experimental. Its API may change in a minor release.
::

## Set up the client entry

This example uses Vue Router and assumes `createApp()` returns the app and router. Keep `createHead()` from `@unhead/vue/server` in the server entry.

In the client entry, install the lazy head as a Vue plugin. Components can keep calling `useHead()` and `useSeoMeta()`.

```ts [src/entry-client.ts]
import { createHead } from '@unhead/vue/lazy'
import { nextTick } from 'vue'
import { createApp } from './main'

const { app, router } = createApp()
const head = createHead()
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  head.finishHydration()

  router.afterEach(async (_to, _from, failure) => {
    if (failure)
      return
    await nextTick()
    await head.load().catch(error => console.error(error))
  })
})
```

This example loads the runtime after the first successful navigation. At that point, Unhead applies the queued entries and handles future updates.

If `<Suspense>` delays the first page, call `head.finishHydration()` on its first `resolve` event. If later pages also wait for `<Suspense>`, call `head.load()` when the new page resolves. With an out-in transition, you can wait for the new page to enter.

If a client value must apply on the first page, call `head.load()` after hydration. Choose the timing in the client entry or framework integration.

## Streaming SSR

Keep `createStreamableHead()` and `wrapStream()` on the server. Omit the `streaming` bundler option so the lazy head can connect to the server queue.

In the client entry, set `streamKey` to the key used by the server. The default server key is `__unhead__`.

```ts
import { createHead } from '@unhead/vue/lazy'

const head = createHead({ streamKey: '__unhead__' })
```

Install the plugin and call `head.finishHydration()` as above. When the framework calls `head.load()`, Unhead applies queued patches and listens for later patches. Call `load()` early if the page needs a streamed stylesheet or script during startup.

When navigation leaves the streamed page, call `head.discardStream()` before loading the destination head. It removes applied stream tags and drops pending and later patches from that page. You can call it even if the runtime has yet to load.

## Pages with no server head

For a client-only app or an SPA fallback, omit `streamKey`. Call `head.finishHydration()` before pushing entries, then call `head.load()` during startup.

## Scripts and plugins

`useScript()` needs the full client head. Await `head.load()` and pass the result explicitly to the Vue composable.

```ts
import { useScript } from '@unhead/vue'

const clientHead = await head.load()
useScript('/analytics.js', { head: clientHead })
```

For direct use outside Vue, import `useScript` from `unhead/scripts` and pass the client head as the first argument.

Hooks and plugins take effect when the runtime loads. Use `lazyPlugins` to load plugin code with the runtime.

```ts
const head = createHead({
  lazyPlugins: () => import('@unhead/vue/plugins').then(m => [m.TemplateParamsPlugin]),
})
```

## Prefetch hints

Check a production build in the Network panel. With the navigation example, the runtime chunk should download after the first successful navigation. If your server adds prefetch or `modulepreload` hints for every chunk, exclude the lazy runtime and any `lazyPlugins` chunks.

## Dev warning

On a buffered SSR page, `finishHydration()` can warn when a queued client tag differs from a server tag. The warning names the tag and, when available, the Vue component. Render the same value on both sides, or call `head.load()` when the client value needs to apply.

See the [lazy head API](/docs/head/api/lazy-head) for options, methods, and load errors.
