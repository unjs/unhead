On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change, usually the first navigation. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

This guide sets up the lazy head in a Vite SSR Vue app with Vue Router. The app follows the [installation guide](/docs/vue/head/guides/get-started/installation), and its `createApp()` returns the app and the router. The same steps fit any setup that hydrates a server render and owns its client entry. Components need no change: `useHead()`, `useSeoMeta()`, and `useScript()` work as before.

Keep `createHead()` from `@unhead/vue/client` in these cases:

- The app renders on the client only.
- A framework creates the head for you. The framework must adopt the lazy head itself.

## What the client entry provides

The lazy head needs three signals that only the client entry has:

| Signal | Call | If the call is missing |
| --- | --- | --- |
| Hydration ended | `head.render()` | A push outside a component, such as from a Vue plugin, counts as server rendered. Its tags wait for a change. Every change loads the runtime at once, even during a navigation pause. The dev warning never runs. |
| A navigation runs | A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause, then `head.render()` when it ends | The runtime loads while the next page still loads. |
| No server head applies | `head.load()` right after you create the head | The first entries count as server rendered, so their tags wait for a change. A page with no server render shows no head until then. |

## Set up the client entry

The server entry keeps `createHead()` from `@unhead/vue/server`. Nothing changes there.

In the client entry, replace `createHead()` with the one from `@unhead/vue/lazy`, and add the hydration and navigation signals:

```ts [src/entry-client.ts]
import { createHead } from '@unhead/vue/lazy'
import { nextTick } from 'vue'
import { createApp } from './main'

const { app, router } = createApp()
const head = createHead()

// Pause head updates while a navigation runs. The pause also holds the load.
let navigating = false
head.hooks.hook('dom:beforeRender', (ctx) => {
  if (navigating)
    ctx.shouldRender = false
})
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  // Hydration has ended.
  head.render()

  router.beforeEach(() => {
    navigating = true
  })
  // Lift the pause after the new page renders, and when the navigation fails.
  const done = () => {
    navigating = false
    head.render()
  }
  router.afterEach(() => nextTick(done))
  router.onError(done)
})
```

Call `head.render()` once hydration ends. Before that call, a `useHead()` call in the `setup()` of a hydrating component adds an entry and loads nothing.

If the route view renders inside `<Suspense>`, `app.mount()` can return before an async `setup()` resolves. That page then pushes its entries after the `head.render()` call. The lazy head counts them as a change, so the page load downloads the runtime. In that case, end hydration on the first `<Suspense>` resolve instead:

1. In the client entry, remove the `head.render()` call after `app.mount()`.
2. In the component that renders `<Suspense>`, call `head.render()` on the first resolve:

```vue [src/App.vue]
<script setup lang="ts">
import { injectHead } from '@unhead/vue'
import { nextTick } from 'vue'

const head = injectHead()
// An async setup() can resolve after app.mount() returns.
// So the first <Suspense> resolve ends hydration, not the client entry.
let hydrating = true
function onResolve() {
  if (hydrating) {
    hydrating = false
    nextTick(() => head.render())
  }
}
</script>

<template>
  <RouterView v-slot="{ Component }">
    <Suspense @resolve="onResolve">
      <component :is="Component" />
    </Suspense>
  </RouterView>
</template>
```

`<Suspense>` also resolves during hydration when no `setup()` is async. So this call ends hydration on every page load. It does not lift the navigation pause. Keep the navigation hooks in the client entry as they are.

Vue Router calls `afterEach` before the new page renders. So the pause lifts in `nextTick()`. By then, the old page has removed its entries, and the new page has added its entries. If a page renders later, such as an async `setup()` inside `<Suspense>`, lift the pause when `<Suspense>` resolves. With `<Transition mode="out-in">` around the route view, read [Page transitions](#page-transitions). The [Pause DOM Rendering](/docs/vue/head/guides/core-concepts/pausing-dom-rendering) guide uses the same pause for the default client head.

To check the result, build the app. Open the network panel, and load a page that does not call `useScript()`. Hydration changes no head element, and no `runtime-<hash>.js` chunk downloads. On the first navigation, that chunk downloads after the new page renders. The head then matches what the default client head shows.

One trigger skips the pause: `useScript()` loads the runtime as soon as its script starts to load. So a page that calls it can download the runtime during the navigation. Its script tag still waits for the pause to lift.

## Page transitions

A `<Transition>` around the route view in the default mode needs no change.

With `mode="out-in"`, the new page mounts after the old page leaves. The pause lifts before that. So the runtime loads while the old page leaves. The head then shows no page tags until the new page mounts. The default client head shows the same gap.

To hold the head until the new page enters, add a second pause in the component that holds the `<Transition>`. The client entry does not change.

```vue [src/App.vue]
<script setup lang="ts">
import { injectHead } from '@unhead/vue'
import { nextTick } from 'vue'

// With mode="out-in", the new page mounts after the old page leaves.
// Hold the head pause from the old page's leave until the new page enters.
const head = injectHead()
let leaving = false
// Only the client renders the DOM
if (!head.ssr) {
  head.hooks?.hook('dom:beforeRender', (ctx) => {
    if (leaving)
      ctx.shouldRender = false
  })
}
function onBeforeLeave() {
  leaving = true
}
// Vue calls this after the new page mounts, so nextTick() runs after its onMounted() hooks
function onEnter() {
  leaving = false
  nextTick(() => head.render())
}
</script>

<template>
  <RouterView v-slot="{ Component }">
    <Transition name="page" mode="out-in" @before-leave="onBeforeLeave" @enter="onEnter">
      <component :is="Component" />
    </Transition>
  </RouterView>
</template>
```

Keep `onEnter()` without a `done` argument. With one, Vue waits for you to call it.

The same hooks work with `<Suspense>` inside an out-in transition. There, the new page runs `setup()` before the old page leaves. The runtime can load then, but the head waits for the new page to enter.

To combine these hooks with the `<Suspense>` resolve from [Set up the client entry](#set-up-the-client-entry), keep one `injectHead()` call, and put `<Suspense @resolve="onResolve">` inside the `<Transition>`.

A navigation that runs no transition, such as a query change on the same page, keeps the pause from the client entry.

## Streaming SSR

Keep `createStreamableHead()` and `wrapStream()` on the server. They write the shell and the queue for streamed tags. Omit the `streaming` bundler option so the lazy head owns the queue.

In the client entry, pass the same `streamKey` as the server. The default server key is `__unhead__`.

```ts [src/entry-client.ts]
import { createHead } from '@unhead/vue/lazy'

const head = createHead({ streamKey: '__unhead__' })
app.use(head)
app.mount('#app')
head.render()
```

Call `head.render()` when hydration ends. If the app uses `<Suspense>`, use the first resolve as shown above.

The framework calls `head.load()` when streamed tags need to apply. Call it early if streamed stylesheets or scripts are needed during page load. If a script must load before hydration can finish, call `head.load()` before awaiting the script.

The runtime drains queued patches in order. Later patches update the same head. For matching tags at the same priority, client entries win.

## Pages with no server head

If a page has no server render, call `head.load()` right after you create the head. An SPA fallback page is one example. Use the flag your server already sets for such a response. The same applies to a head that you create after hydration ended.

If a load starts before hydration ends and before any change, the head assumes that no server head applies. The runtime then adopts nothing and renders the entries as they are. `head.load()` is safe to call more than once. It resolves `false` if the load fails.

## Prefetch hints

Vite loads the dependencies of a dynamic import when the import runs. So by default, the runtime chunk downloads on the first change. If your server adds a prefetch or `modulepreload` hint for every chunk, the browser downloads the runtime at once. Leave out the lazy head chunks:

- The runtime. Vite builds it from `unhead/dist/chunks/runtime.mjs` as `runtime-<hash>.js`.
- The chunk that your `lazyPlugins` loader imports, if you use one.

## What loads the runtime

After hydration, the first head change loads the runtime. The runtime renders the whole head and handles every later change. These also load it:

| Trigger | When the runtime loads |
| --- | --- |
| A call during hydration from a mounted component, or from a component that the server did not render | At once. Example: `useHead()` in `onMounted()`. |
| A patch or dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When its script starts to load. With the default trigger, that is when the component mounts. |
| `head.load()` | At once. Call it at idle to apply client only values without a change. |

A patch with the same input as before loads nothing. A reactive input resolves again when the router sets the route during hydration, and that patch changes nothing.

The lazy head compares plain objects, lists, and primitive values. `useHead()` resolves refs and getter functions before the comparison. The lazy head cannot compare another object, such as a promise. A patch that holds one loads the runtime. A `titleTemplate` function and an event handler, such as `onload`, compare by reference.

## Plugins and libraries that push head tags

Plugin setup runs when you create the head. Most plugin hooks, such as a `tags:resolve` listener, take effect when the runtime loads. These hooks run before the load:

- `entries:updated` runs on each push and dispose, and on each patch that changes the input. During hydration, an in-place edit to an input does not run it. The lazy head treats that edit as server rendered.
- `dom:beforeRender` runs on each change after hydration, because the lazy head checks for a pause. Its `tags` list is empty.
- In development, the dev check resolves the tags once after hydration, so the resolve hooks run then.

To keep plugin code out of the eager bundle, pass a loader to `lazyPlugins`. It runs together with the runtime import. In development, it also runs for the dev check:

```ts
const head = createHead({
  lazyPlugins: () => import('@unhead/vue/plugins').then(m => [m.TemplateParamsPlugin]),
})
```

A library entry that changes on a navigation loads the runtime, as any other entry does. After hydration, each new push loads the runtime, even if its input matches an existing entry. A dispose loads it too. If a library keeps the same input across pages, it can keep one entry and patch it. A patch with the same input loads nothing.

## Recover from a failed load

If the runtime chunk fails to load, the document keeps its current head. The `onLoadError` option receives the error, and a later change or `head.load()` tries again. A browser may keep a failed `import()` for the page, so a retry can fail too. Use `onLoadError` to recover, for example with a full page load on the next navigation. In the client entry:

```ts [src/entry-client.ts]
let reloadOnNavigation = false
const head = createHead({
  onLoadError: () => {
    reloadOnNavigation = true
  },
})

router.beforeEach((to) => {
  if (reloadOnNavigation) {
    window.location.assign(to.fullPath)
    return false
  }
})
```

## Dev warning

A tag that the client renders differently from the server waits for the first change. Crawler tags, such as `og:` meta tags and JSON-LD, wait too. In development, the lazy head checks for such tags after hydration. It resolves the tags the client would render and compares them with the server head in the document. The check changes nothing in the document.

The console shows one warning for each tag, with the file of the component that pushed it. The lazy head keeps a list of warned tags for the browser tab. So a tag that differs on every page warns once. For example:

```txt
[unhead] <meta name="theme-color"> differs from the server head in content. Pushed by /app/src/components/ColorMode.vue. It applies on the first head change. Push the same input on the server and the client, or call head.load().
```

The check compares the title and the html and body attributes. It also compares the `base`, `meta`, `link`, `script`, `style`, and `noscript` tags. It stays silent for a tag that the server rendered and the client does not push. It does not run if the runtime already loads. A production build holds no code for it.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| A client value that differs from the server value, such as one that reads `import.meta.env.SSR` or the color mode | The document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, or call `head.load()` after hydration. |
| `useHead()` in `onBeforeMount()` of a hydrating component, behind `import.meta.env.SSR` in `setup()`, or in a Vue plugin install | The head counts the call as server rendered, so the tag waits for a change. | Call it in `setup()` on both sides, or in `onMounted()`. In a plugin, call `head.load()` after the call. |
| A router with no navigation hooks | Nothing pauses the load, so it can start while the next page loads. | Pause with a `dom:beforeRender` hook from your own navigation code, and call `head.render()` when the navigation ends. |
