On a server rendered page, the server already wrote the right head tags. `createLazyHead()` from `@unhead/vue/lazy` keeps head entries in memory during hydration and leaves those tags alone. The DOM runtime loads later, from a separate chunk.

::note
The lazy head is experimental. Its API may change in a minor release.
::

Use the lazy head when the server renders the head of every page. Keep `createHead()` from `@unhead/vue/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/vue/head/guides/core-concepts/streaming). The lazy head does not support streaming.

## Setup

Replace `createHead()` in the client entry. The server entry does not change, and `useHead()` works as before.

```ts [src/entry-client.ts]
import { createLazyHead } from '@unhead/vue/lazy'
import { createApp } from './main'

const { app, router } = createApp()
const head = createLazyHead()
app.use(head)

router.isReady().then(() => {
  app.mount('#app')
  // Hydration has ended.
  head.render()
})
```

Call `head.render()` once hydration ends. Before that call, a `useHead()` call in a hydrating component adds an entry and loads nothing. After that call, a head change loads the runtime, unless a [load block](#block-the-load-during-navigation) or a [pause](#pause-dom-updates) blocks it.

After hydration, the document still holds the server tags. The browser fetches no runtime chunk yet.

## When the runtime loads

| Trigger | When the runtime loads |
| --- | --- |
| The browser is idle | When the idle callback runs. A browser without `requestIdleCallback()` uses a short timer. |
| A change after hydration | At once. Examples: a ref in `useHead()` changes, or a new page calls `useHead()`. |
| A call the server never ran | At once. Examples: `useHead()` in `onMounted()`, or in a component that mounts after hydration. |
| A patch or dispose during hydration | At once, because the client already differs from the server. |
| `head.load()` | At once. |
| `useScript()` | When its trigger adds the script to the document. |

Once loaded, the head renders each change, as the standard client head does.

If a page is not server rendered, call `head.load()` after you create the head:

```ts
await head.load()
```

`head.load()` is safe to call more than once. It resolves `false` if the chunk fails to load. The `onLoadError` option receives the error, and a later change or `head.load()` tries again.

## Block the load during navigation

An idle load or a head change can start the load while the next page still loads. Call `head.blockLoad()` when a navigation starts, and `head.render()` when it ends:

```ts [src/entry-client.ts]
router.isReady().then(() => {
  app.mount('#app')
  head.render()

  // Block the load while a navigation runs.
  router.beforeEach(() => {
    head.blockLoad()
  })
  // Release it when the navigation ends, even if it failed.
  router.afterEach(() => {
    head.render()
  })
  router.onError(() => {
    head.render()
  })
})
```

`blockLoad()` cancels a pending idle load and blocks changes. `head.render()` releases the load block. If entries changed during the load block, the runtime loads at once. If nothing changed, the idle load starts again. A direct `head.load()` still runs during a load block.

Add the guards after `head.render()`. `blockLoad()` also marks the end of hydration, so a load block during the first navigation ends hydration too early.

## Pause DOM updates

The [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause also blocks the load. While a hook sets `shouldRender` to `false`, the idle load and changes after hydration wait. Call `head.render()` after you lift the pause, as the [Pause DOM Rendering](/docs/vue/head/guides/core-concepts/pausing-dom-rendering) guide shows.

A patch or dispose during hydration still loads the runtime while paused. The runtime then writes nothing to the document until the pause lifts.

## Plugins and template params

Plugin setup runs when you create the head. Plugin hooks take effect when the runtime loads.

To keep plugin code out of the eager chunk, pass a loader to `lazyPlugins`. It runs when the runtime loads:

```ts
const head = createLazyHead({
  lazyPlugins: () => import('./head-plugins').then(m => [m.analyticsPlugin]),
})
```

On the client, pass `lazyTemplateParams` in place of `TemplateParamsPlugin`. It loads the plugin only when the runtime needs it:

```ts
import { createLazyHead, lazyTemplateParams } from '@unhead/vue/lazy'

const head = createLazyHead({ plugins: [lazyTemplateParams] })
```
