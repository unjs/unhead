---
title: compileTags()
description: API reference for unhead/compiled, the entry for module authors and tooling. compileTags() and dynamicValue() turn head input into compiled tags, and readEntry() reads any head entry as head input.
---

```ts
import { compileTags } from 'unhead/compiled'

const result = compileTags({
  title: 'Home',
  meta: [{ name: 'description', content: 'Welcome' }],
})
if (result._tag === 'Ok')
  head.push(result.tags)
```

`compileTags()`{lang="ts"} turns static head input into compiled tags. It applies the same normalize, dedupe, and weight rules as a normal call. It keeps no state and never throws. If it cannot prove the input, it returns `Bail` with a reason.

The bundler [`compile` option](/docs/vue/head/guides/core-concepts/compiler-mode) calls it for you. Call it yourself for head input that a component does not own, such as a static app head.

::note
`compileTags()`, `dynamicValue()`, `readEntry()`, and the compiled tag format are experimental. They may change in a minor release.
::

All three functions come from `unhead/compiled`, for module authors and tooling. A bundler keeps only the functions you import, so `readEntry()` alone adds no compiler code.

## API Reference

```ts
function compileTags(input: unknown, options?: CompileOptions): CompileResult

type CompileResult
  = | { _tag: 'Ok', tags: CompiledTags, valueCount: number }
    | { _tag: 'Bail', reason: string }

interface CompileOptions {
  /** The number of dynamic values in the input. */
  dynamicValues?: number
  /** The `tagPriority` entry option, held in each tag. */
  tagPriority?: number | 'critical' | 'high' | 'low'
}
```

Push compiled tags with `head.push(compiledTags)` on a compiled server head or a lazy head. Treat `CompiledTags` as opaque data. Store it at module scope, so every request shares one set of compiled tags.

## Entry priority

An entry option takes the entry off the server memo. To give every tag of an entry one priority, pass `tagPriority` to `compileTags()` and push the compiled tags with no options:

```ts
import { compileTags } from 'unhead/compiled'

// the same tags as head.push(input, { tagPriority: 'low' })
const result = compileTags({ templateParams: { site: { name: 'My Site' } } }, { tagPriority: 'low' })
if (result._tag === 'Ok')
  head.push(result.tags)
```

Template params cannot hold a priority in their input, so this is the only way to keep a low priority `templateParams` entry compiled. A `before:` or `after:` priority returns `Bail`.

## Dynamic values

`dynamicValue(index)` returns a token that marks dynamic value `index` in a string value. Set `dynamicValues` to the number of dynamic values. Pass their values as `values` when you push the compiled tags:

```ts
import { compileTags, dynamicValue } from 'unhead/compiled'

const result = compileTags({
  script: [{ id: 'app-data', type: 'application/json', innerHTML: dynamicValue(0) }],
}, { dynamicValues: 1 })

if (result._tag === 'Ok')
  head.push(result.tags, { values: [JSON.stringify(data)] })
```

A dynamic value cannot decide the identity, weight, or merging of a tag. For example, a dynamic value in `meta.name` or in `class` returns `Bail`. The [Dynamic values](/docs/vue/head/guides/core-concepts/compiler-mode#dynamic-values) section lists these places.

## readEntry()

```ts
function readEntry(entry: HeadEntry<any>, head: Unhead<any>): EntryReading

interface EntryReading {
  /** The entry as head input. */
  input: ResolvableHead
  /** True for an entry from a `useSeoMeta()` call. */
  seoMeta: boolean
  /** True when the entry holds compiled tags. */
  compiled: boolean
  /** The path of each dynamic value in `input`, such as `meta.0.content`. */
  dynamic?: string[]
}
```

Reads an entry of `head.entries` as head input. It reads every entry of every head: compiled tags, normal input, and a patch that waits for a render. It does not render.

- A patch that waits for the runtime comes first.
- Values settle. On the compiled server head, the `values` function of an entry runs now, once. The first render then uses the same values.
- Normal input resolves through the prop resolvers of the head. So a Vue ref reads as its value, and a getter runs.
- The flat meta of a `useSeoMeta()` call unpacks to meta tags. `readEntry()` uses the `FlatMetaPlugin` of the head for this, so it adds no unpack code.

`seoMeta` is `true` for an entry from a `useSeoMeta()` call, compiled or not. It is also `true` for an entry pushed with the `seoMeta` option. So a module reads the page title and description the same way with compiler mode on or off:

```ts
import { readEntry } from 'unhead/compiled'

for (const entry of head.entries.values()) {
  const { input, seoMeta } = readEntry(entry, head)
  if (seoMeta) {
    const description = input.meta?.find(meta => meta.name === 'description')?.content
    console.log(input.title, description)
  }
}
```

The input is a new object on each read, so you can change it. A change to it does not change the head.

`dynamic` lists the path of each dynamic value of compiled tags, such as `title` or `meta.0.content`. A dynamic value can change on each render, and the server memo holds a token in its place. A static value is the same on every render. `dynamic` is `undefined` when every value is static, and for normal input, which never takes the memo. A tag transform uses it in `cacheKey`: a static relative image URL keeps the memo, and a dynamic one returns `null`.

```ts
const { input, dynamic } = readEntry(entry, head)
input.meta?.forEach((meta, i) => {
  const isDynamic = dynamic?.includes(`meta.${i}.content`)
})
```

## The seoMeta push option

A module that pushes compiled tags for a `useSeoMeta()` call marks them with the `seoMeta` option. `readEntry()` then reports `seoMeta: true`, as for the call itself:

```ts
head.push(compiledTags, { seoMeta: true })
```

The compiled server head and the lazy head keep the option out of the entry options, so the entry keeps the server memo.
