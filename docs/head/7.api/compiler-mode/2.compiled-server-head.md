---
title: Compiled Server Head
description: API reference for the server half of compiler mode, the head that renders compiled tags, plus renderSSRHead() and transformHtmlTemplate().
---

```ts
import { createHead } from '@unhead/vue/compiled/server'

const head = createHead()
app.use(head)
```

The compiled server head is the server half of [compiler mode](/docs/vue/head/guides/core-concepts/compiler-mode#server-half). It renders compiled tags and normal input. It produces the same HTML as the server head from `@unhead/vue/server`. A head with no render hook listeners takes a faster path for its compiled tags.

::note
The compiled server head and its exports are experimental. Their API may change in a minor release.
::

## Entry points

| Entry point | Exports |
| --- | --- |
| `@unhead/vue/compiled/server` | `createHead`, `renderSSRHead`, `transformHtmlTemplate` |
| `unhead/compiled/server` | `createHead`, `renderSSRHead`, `transformHtmlTemplate`, [`compileTags`, `dynamicValue`](/docs/head/api/compiler-mode/compile-tags) |

These entries hold only the functions that render compiled tags. Import the other server utilities, such as `propsToString()`, `prepareTemplate()`, `prepareHeadInput()`, and `VueHeadMixin`, from `unhead/server` or `@unhead/vue/server`. They work with the compiled server head.

`@unhead/vue/compiled/server` also exports `useCompiledHead()` and `useCompiledSeoMeta()`. The bundler `compile` option writes calls to them. Do not call them yourself.

## createHead()

```ts
// @unhead/vue/compiled/server
function createHead(options?: Omit<CompiledServerHeadOptions, 'propResolvers'>): CompiledVueServerHead

// unhead/compiled/server
function createHead<T>(options?: CompiledServerHeadOptions): CompiledServerUnhead<T>
```

The options are the options of the server `createHead()`. The `init` option also takes compiled tags. The Vue export sets `propResolvers` itself.

`head.push(input, options)` takes normal input or compiled tags. Pass dynamic values as `options.values`. The `values` option can be an array, or a function that runs once, before the first render reads it.

The `input` of a compiled entry reads as the head input it came from, so a module that reads `head.entries` works as without compiler mode.

These make the head use the v3 render path for every render. The output stays the same:

- A listener on a render hook: `entries:resolve`, `entries:normalize`, any `tags:` hook, `ssr:beforeRender`, `ssr:render`, or `ssr:rendered`.
- A custom `tagWeight` option.
- A custom prop resolver on the `unhead/compiled/server` head.

`TemplateParamsPlugin` and `InferSeoMetaPlugin` run on the faster path. So does a plugin with a [tag transform](/docs/nuxt/head/guides/framework-integration/compiler-mode#change-tags-from-a-module).

## renderSSRHead()

```ts
function renderSSRHead(head: Unhead<any>, options?: RenderSSRHeadOptions): SSRHeadPayload
```

Renders a head to its HTML parts, through the fastest path the head allows. `transformHtmlTemplate()` calls it for you, through `head.render()`. The `renderSSRHead()` of `unhead/server` renders a compiled server head too, with the same output, but always on the slower v3 path.

## transformHtmlTemplate()

```ts
function transformHtmlTemplate(head: Unhead<any>, html: string | PreparedTemplate): string
```

Renders the head into an HTML template, as the `unhead/server` export does.
