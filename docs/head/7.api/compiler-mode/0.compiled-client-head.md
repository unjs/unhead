---
title: Compiled Client Head
description: API reference for the client half of compiler mode, the head that loads its DOM runtime on the first head change or at idle.
---

```ts
import { createHead } from '@unhead/vue/compiled/client'

const head = createHead()
app.use(head)
```

The compiled client head is the client half of [compiler mode](/docs/vue/head/guides/core-concepts/compiler-mode#client-half), for a server rendered page. It stores entries without touching the document. It loads the standard DOM runtime on the first head change, at idle with `load: 'idle'`, or when `load()` runs.

::note
The compiled client head is experimental. Its API may change in a minor release.
::

## Entry points

| Entry point | Exports |
| --- | --- |
| `@unhead/vue/compiled/client` | `createHead` |
| `unhead/compiled/client` | `createHead` |

The Vue export adds the Vue plugin install, detects calls the server never ran, and names components in the dev warning. Use `unhead/compiled/client` only to build an adapter for another framework.

## API Reference

```ts
function createHead(options?: CompiledClientHeadOptions): CompiledVueClientHead
```

### Options

`CompiledClientHeadOptions` takes every option of the client `createHead()`, plus these:

| Option | Type | Description |
| --- | --- | --- |
| `load` | `'change' \| 'idle'` | When the runtime loads after hydration. `'change'`, the default, loads on the first head change. `'idle'` loads at browser idle. |
| `lazyPlugins` | `() => Promise<HeadPluginInput[]>` | Plugins that load with the runtime. Their code stays out of the eager chunk. |
| `onLoadError` | `(error: unknown) => void` | Receives the error when the runtime chunk fails to load. The default logs with `console.error`. |
| `isClientOnlyPush` | `() => boolean` | For adapters. Returns `true` when the current push cannot be in the server rendered head. During hydration, such a push loads the runtime at once. The Vue export sets it. |
| `entrySource` | `() => string \| undefined` | For adapters. Names the code that pushes an entry, for the dev warning. The Vue export sets it to the component. |

### Returns

The head has the methods of the client head, plus these:

| Method | Description |
| --- | --- |
| `load()` | Loads the runtime now. Safe to call more than once. Resolves `true` on success and `false` on failure. |
| `blockLoad()` | Blocks the load during a navigation. The next `render()` releases it. A direct `load()` still runs. |
| `render()` | Before the runtime loads, it marks the end of hydration and releases a load block. If entries changed, it loads at once, unless a `dom:beforeRender` pause blocks it. Otherwise it loads nothing. After the runtime loads, it renders. |

## Dev warning

In development, the first `render()` checks the tags the client would render against the server head in the document. It warns once per page for each client tag that is missing or different. It does not run with `load: 'idle'`. Read [Dev warning](/docs/vue/head/guides/core-concepts/compiler-mode#dev-warning) for the message and the fix.

The check reads `process.env.NODE_ENV`. A production build replaces it with `'production'` and drops the check.

## Template params

Pass `TemplateParamsPlugin` in `plugins`, as on the client head. To keep its code out of the eager chunk, pass it in `lazyPlugins`, so it loads with the runtime.
