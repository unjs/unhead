---
title: useCompiledHead()
description: API reference for useCompiledHead() and useCompiledSeoMeta(), the Vue composables that the compile option emits for compiled head calls.
---

The bundler [`compile` option](/docs/vue/head/guides/core-concepts/compiler-mode) replaces each compiled `useHead()` call with `useCompiledHead()`, and each compiled `useSeoMeta()` call with `useCompiledSeoMeta()`. You rarely call them yourself.

::note
`useCompiledHead()` and `useCompiledSeoMeta()` are experimental. Their API may change in a minor release.
::

For example, the build turns this call:

```ts
useHead({
  title: () => post.value.title,
  meta: [{ name: 'description', content: 'A post' }],
})
```

into module scope compiled tags and a `useCompiledHead()` call with one dynamic value. This output is illustrative, and the compiled tag format is internal:

```ts
import { useCompiledHead as __unhead_useCompiledHead } from '@unhead/vue/compiled'

const __unhead_0 = [/* the normalized tags, with a token for dynamic value 0 */]
__unhead_useCompiledHead(__unhead_0, [() => post.value.title])
```

## API Reference

Both functions come from `@unhead/vue/compiled`.

```ts
function useCompiledHead(
  compiledTags: CompiledTags,
  values?: readonly unknown[],
  options?: UseHeadOptions,
): ActiveHeadEntry<any>

function useCompiledSeoMeta(
  compiledTags: CompiledTags,
  loose: (values: unknown[]) => object,
  values: readonly unknown[],
  options?: UseHeadOptions,
): ActiveHeadEntry<any>
```

| Parameter | Description |
| --- | --- |
| `compiledTags` | The compiled tags of the call. |
| `values` | The dynamic values, in source order. Refs, computed refs, and getters stay reactive. |
| `loose` | Rebuilds the `useSeoMeta()` input from the dynamic values. The entry uses it when a dynamic value needs the standard flat meta rules. |
| `options` | Entry options. Compiled calls pass only `head`. |

Both return the active entry, as `useHead()` does.

## Behavior

Compiled tags render on a head that takes them. `@unhead/vue/compiled/server` and `@unhead/vue/compiled/server-strict` create such heads. A lazy head from `@unhead/vue/lazy` takes compiled tags once `acceptCompiledTags()` runs, and the first call runs it. Any other head, such as a full runtime head, makes the call throw. The error names the entries that create a head for compiled tags, and says how to turn off `compile`. The build turns off compiler mode when the app creates a full runtime head itself, so this error is rare.

On the server, a ref, computed ref, or getter resolves once, at the first render. On the client, one effect tracks every dynamic value of the call. A call with no dynamic values creates no effect.

On the client, the entry follows the component lifecycle, as `useHead()` does. Unmount disposes it, and `<KeepAlive>` deactivates and activates it. Outside a component, the entry disposes with its effect scope.

Under the `node` export condition, `@unhead/vue/compiled` contains the server half only.
