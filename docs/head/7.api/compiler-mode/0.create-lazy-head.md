---
title: createLazyHead()
description: API reference for createLazyHead(), the client head that loads its DOM runtime lazily.
---

```ts
import { createLazyHead } from '@unhead/vue/lazy'

const head = createLazyHead()
app.use(head)
```

`createLazyHead()`{lang="ts"} creates a client head for a server rendered page. It stores entries without touching the document. It loads the DOM runtime at idle, or when a change must reach the document. Read the [Lazy Head guide](/docs/vue/head/guides/core-concepts/lazy-head) for setup and load triggers.

::note
`createLazyHead()` is experimental. Its API may change in a minor release.
::

## Entry points

| Entry point | Exports |
| --- | --- |
| `@unhead/vue/lazy` | `createLazyHead` |
| `unhead/lazy` | `createLazyHead` |

The Vue export adds the Vue plugin install and detects calls the server never ran. Use `unhead/lazy` only to build an adapter for another framework.

## API Reference

```ts
function createLazyHead(options?: CreateLazyHeadOptions): VueLazyHead
```

### Options

`CreateLazyHeadOptions` takes every option of the client `createHead()`, plus these:

| Option | Type | Description |
| --- | --- | --- |
| `lazyPlugins` | `() => Promise<HeadPluginInput[]>` | Plugins that load with the runtime. Their code stays out of the eager chunk. |
| `onLoadError` | `(error: unknown) => void` | Receives the error when the runtime chunk fails to load. The default logs with `console.error`. |
| `isClientOnlyPush` | `() => boolean` | Returns `true` when the current push cannot be in the server rendered head. During hydration, such a push loads the runtime at once. The Vue export sets it. |

A custom `render` option makes the head use the full runtime.

### Returns

The head has the methods of the client head, plus these:

| Method | Description |
| --- | --- |
| `push(input, options?)` | Adds normal input or compiled tags. Pass dynamic values as `options.values`. Returns an entry with `patch()` and `dispose()`. |
| `load()` | Loads the runtime now. Safe to call more than once. Resolves `true` on success and `false` on failure. |
| `blockLoad()` | Blocks the load during a navigation, and cancels a pending idle load. The next `render()` releases it. A direct `load()` still runs. |
| `render()` | Before the runtime loads, it marks the end of hydration and releases a load block. If entries changed, it loads at once, unless a `dom:beforeRender` pause blocks it. Otherwise it arms the idle load. After the runtime loads, it renders. |

`push()` and `patch()` take `LazyEntryOptions`. It adds `values?: readonly unknown[]`, the values for the dynamic values of compiled tags.

## Compiled tags

The lazy head takes compiled tags with no other setup. When every entry holds compiled tags, it loads the compiled runtime. Otherwise it loads only the full runtime, which also renders compiled tags. It also loads only the full runtime for a `render` option, and for a hook listener that the compiled runtime cannot run. To read the compiled tags of an entry, use [`readCompiledEntry()`](/docs/head/api/compiler-mode/compile-tags#readcompiledentry) from `unhead/compiled`.

## Template params

Pass `TemplateParamsPlugin` in `plugins`, as on the client head. Both runtimes run it. To keep its code out of the eager chunk, pass it in `lazyPlugins`, so it loads with the runtime.
