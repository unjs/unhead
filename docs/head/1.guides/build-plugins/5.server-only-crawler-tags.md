The server-only crawler tags transform removes crawler tags from `useHead()` and `useSeoMeta()` calls in client builds. The server still renders every tag. It is disabled by default.

## Why

Crawlers read the HTML the server sends. Googlebot renders each URL from a fresh request, and social crawlers read the raw HTML. Neither sees head changes that happen after a client navigation.

So on the client, crawler tags only cost bytes: their values, and for `useSeoMeta()` the code that unpacks them. When a `useSeoMeta()` call has no other keys, the call goes, and `unpackMeta` can leave the client bundle.

## Crawler tags

The transform removes these tags, and only these:

| Tag | `useHead()` | `useSeoMeta()` keys |
| --- | --- | --- |
| Open Graph | `meta` with `property` or `name` starting `og:` | `ogTitle`, `ogImage`, `ogDescription`, other `og*` keys |
| Twitter | `meta` with `name` starting `twitter:` | `twitterCard`, `twitterTitle`, other `twitter*` keys |
| Article | `meta` with `property` starting `article:` | `articleAuthor`, `articlePublishedTime`, other `article*` keys |
| Description | `meta` with `name="description"` | `description` |
| Robots | `meta` with `name="robots"` | `robots` |
| Keywords | `meta` with `name="keywords"` | `keywords` |
| Canonical | `link` with `rel="canonical"` | none |
| Language alternates | `link` with `rel="alternate"` and `hreflang` | none |
| Structured data | `script` with `type="application/ld+json"` | none |

Every other tag stays on the client. This includes the title, `titleTemplate`, html and body attributes, styles, scripts, stylesheets, icons, and the meta tags browsers act on, such as `theme-color`, `color-scheme`, and `viewport`.

::code-group

```ts [Before (source)]
useSeoMeta({
  title: 'My Page',
  description: 'My description',
  ogTitle: 'My Page',
  ogImage: () => post.value.image,
  twitterCard: 'summary_large_image',
})
useHead({
  link: [
    { rel: 'canonical', href: 'https://example.com/my-page' },
    { rel: 'stylesheet', href: '/page.css' },
  ],
})
```

```ts [After this transform (client build)]
useSeoMeta({
  title: 'My Page',
})
useHead({
  link: [
    { rel: 'stylesheet', href: '/page.css' },
  ],
})
```

::

A call left with no input goes. A call whose result is assigned stays, with an empty input.

## Setup

Enable the transform in the [unified Vite plugin](/docs/head/guides/build-plugins/overview):

```ts
import { Unhead } from '@unhead/vue/vite'

export default defineConfig({
  plugins: [Unhead({ serverOnlyCrawlerTags: true })],
})
```

The transform needs server rendering or prerendering. In a client-only app, crawlers would see no crawler tags.

## Options

```ts
Unhead({
  serverOnlyCrawlerTags: {
    // Other modules that export useHead() or useSeoMeta()
    importPaths: ['#my-head'],
    // Override the shared file filter for this transform only
    filter: { exclude: [/keep-crawler-tags/] },
  },
})
```

| Option | Type | Default | Description |
| -------- | -------- | --------- | ------------- |
| `importPaths` | `string[]` | Unset | Extra import paths for `useHead()` and `useSeoMeta()`. Unhead packages and the Nuxt auto-imports are always read |
| `filter` | `object` | inherited | Include/exclude file patterns for the transform only (overrides the shared `filter`). The runtime plugin ignores it |

## What changes on the client

- **Server HTML:** unchanged. Server builds keep every tag.
- **Hydration:** crawler tags keep their server values. The client never writes, changes, or removes a crawler tag, whatever its source.
- **After a client navigation:** crawler tags keep the values of the first page the server rendered. The title, attributes, styles, and scripts update as before.

Googlebot runs JavaScript when it renders a page. So the DOM it indexes must hold the server values, including where a module pushes its own defaults on the client.

If something on the client reads a crawler tag after navigation, such as a share button that reads `og:url`, turn the option off. The `filter` option cannot help here. It keeps a file's crawler tags in the bundle. The runtime plugin still keeps them out of the DOM, whatever file pushed them.

## Limitations

The transform reads only input it can analyse at build time:

- An input object literal, or a getter that returns one: `useHead(() => ({ ... }))`.
- A tag whose identity is a string literal, such as `name: 'description'`. The identity is `name`, or `property` when the tag has no `name`. For a `link`, it is `rel` and `hreflang`. For a `script`, it is `type`. A tag with a spread or a dynamic identity stays.
- A value that runs no code of yours when the client evaluates it. Literals, variables, and getters such as `() => post.value.title` qualify. So do `computed()` and `ref()` from Vue, and `JSON.stringify()` of a literal.
- Any other call keeps the tag, including `t()` and `toValue()`. A property read such as `post.value.title` keeps the tag, because it can run a getter. A template literal with a variable keeps the tag, because it can call `toString()`. To remove such a tag, wrap the value in a getter.

Tags from other sources stay in the client bundle: a dynamic input such as `useHead(input)`, `head.push()`, `entry.patch()`, and modules that add tags at runtime. A runtime plugin removes their crawler tags before the client renders, so the server values stay in the DOM. See [How it works](#how-it-works).

## How It Works

The option has two parts.

The transform runs on client builds only, before the [`useSeoMeta` transform](/docs/head/guides/build-plugins/seo-meta-transform). It finds `useHead()`, `useHeadSafe()`, and `useSeoMeta()` calls imported from Unhead packages, or auto-imported, and removes crawler tags from their input. A `useSeoMeta()` call it simplifies can then become a plain `useHead()` call.

The plugin also registers `ServerOnlyCrawlerTagsPlugin` from `unhead/plugins` on every client head. It wraps the options of each `createHead()` call imported from `unhead/client`, including the calls inside framework packages. A named import and a namespace import both count. A local function that shadows the import does not. The runtime plugin removes every tag on the crawler tag list from the resolved client tags. So the DOM renderer never writes, changes, or removes a crawler tag.

A head from another source, such as `createUnhead()`, does not get the runtime plugin. Neither does a `createHead()` called through a variable, a local re-export, or a dynamic import. Register it with `head.use(ServerOnlyCrawlerTagsPlugin)`.

With the option off, the build never imports the runtime plugin, so the option costs no bytes. Plain Rollup builds have no client or server target, so neither part runs there.

Like [tree-shaking](/docs/head/guides/build-plugins/tree-shaking), both parts skip the dev server.
