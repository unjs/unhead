On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

This guide is for the code that owns the client entry: a framework integration or a custom Vite SSR setup. Components need no change. `useHead()`, `useSeoMeta()`, and `useScript()` work as before.

::warning
React hydrates each `<Suspense>` boundary after the rest of the page. A `useHead()` call inside a boundary adds its entry after hydration ended, so it loads the runtime right after hydration. The head stays correct, but the load is no longer lazy. The lazy head saves bytes only when the `useHead()` calls of the first page sit outside `<Suspense>`.
::

## What the client entry provides

The lazy head needs three signals that only the client entry has:

| Signal | Call | If the call is missing |
| --- | --- | --- |
| Hydration ended | `UnheadProvider` from `@unhead/react/lazy` calls `head.render()` | Every entry counts as server rendered, so a component that mounts after hydration shows no tags until a change. The dev warning never runs. |
| A navigation runs | A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause, then `head.render()` when it ends | The runtime loads while the next page still loads. |
| No server head applies | `head.load()` right after you create the head | The first entries count as server rendered, so their tags wait for a change. A page with no server render shows no head until then. |

`useHead()` adds its entry in an effect, and React runs the effects of children before the effect of their parent. So the provider calls `head.render()` from its own effect, after the entries of the hydrated page exist. Do not call `head.render()` right after `hydrateRoot()`. At that time, no entry exists yet.

Keep `createHead()` from `@unhead/react/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/react/head/guides/core-concepts/streaming). The lazy head does not support streaming.

## Setup

Import `createHead()` and `UnheadProvider` in the client entry from `@unhead/react/lazy`. The provider from `@unhead/react/client` adds the DOM runtime to the eager chunk, so do not use it with the lazy head.

```ts [src/head.ts]
import { createHead } from '@unhead/react/lazy'

export const head = createHead()

// Pause head updates while a navigation runs. The pause also holds the load.
let navigating = false
head.hooks.hook('dom:beforeRender', (ctx) => {
  if (navigating)
    ctx.shouldRender = false
})

// Call this when your router starts a navigation.
export function startNavigation() {
  navigating = true
}

// Call this after the new page renders, and when the navigation fails.
export function endNavigation() {
  navigating = false
  head.render()
}
```

```tsx [src/entry-client.tsx]
import { UnheadProvider } from '@unhead/react/lazy'
import { StrictMode } from 'react'
import { hydrateRoot } from 'react-dom/client'
import App from './App'
import { head } from './head'

hydrateRoot(
  document.getElementById('root') as HTMLElement,
  <StrictMode>
    <UnheadProvider value={head}>
      <App />
    </UnheadProvider>
  </StrictMode>,
)
```

Call `endNavigation()` from an effect of the layout that renders the page, and run it again on each new location. React runs that effect after the effects of the new page, so the new entries exist. The server keeps `createHead()` and `UnheadProvider` from `@unhead/react/server`. Nothing changes there.

## What loads the runtime

After hydration, the first head change loads the runtime. The runtime renders the whole head, and it handles every later change. A re-render that passes an equal input to `useHead()` is no change.

| Trigger | When the runtime loads |
| --- | --- |
| A state change that changes the input of `useHead()` | At once, unless a pause holds it. |
| A component that mounts after hydration | At once, unless a pause holds it. |
| A dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When it adds its script to the document. |
| `head.load()` | At once. Call it at idle to apply client only values without a change. |

The lazy head compares plain objects, lists, and primitive values. A function value, such as a getter, counts as a change, so it loads the runtime once hydration ends. Read [What a change does](/docs/vue/head/guides/core-concepts/lazy-head#what-a-change-does) for the full rules. They are the same for every framework.

## Dev warning

In development, the lazy head checks the tags the client would render against the server head after hydration. The console names each tag that waits for the first change. React gives no component name to the lazy head, so the warning names the tag only. Read [Dev warning](/docs/vue/head/guides/core-concepts/lazy-head#dev-warning) for the message and the fix.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| Streaming SSR | The lazy head does not support streaming. | Keep `createHead()` from `@unhead/react/client`. |
| `<StrictMode>` in development | React runs each effect twice. The first dispose loads the runtime after hydration, so the dev warning does not run. Production builds run each effect once. | To see the dev warning, render once without `<StrictMode>`. |
| A component that renders a different tree on the client during hydration | React has no public signal for a component that hydrates. The head counts its entry as server rendered, so its tags wait for a change. The dev warning names the tag. | Render the same tree on both sides, or call `head.load()` after hydration. |
| `useHead()` inside a `<Suspense>` boundary | React hydrates the boundary after the provider effect. Its entries arrive after hydration ended, so they load the runtime. The head keeps one copy of each tag. | Call `useHead()` for the first page outside `<Suspense>`, or keep `createHead()` from `@unhead/react/client`. |
| A value that the client computes differently from the server | The document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, or call `head.load()` after hydration. |
| The runtime chunk fails to load | The document keeps its current head. | Use the `onLoadError` option to recover, for example with a full reload on the next navigation. |
