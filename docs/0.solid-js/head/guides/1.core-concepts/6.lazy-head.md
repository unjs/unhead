On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

This guide is for the code that owns the client entry: a framework integration or a custom Vite SSR setup. Components need no change. `useHead()`, `useSeoMeta()`, and `useScript()` work as before.

## What the client entry provides

The lazy head needs three signals that only the client entry has:

| Signal | Call | If the call is missing |
| --- | --- | --- |
| Hydration ended | `head.render()` right after `hydrate()` returns | A push outside a component, such as from the client entry, counts as server rendered, so its tags wait for a change. The dev warning never runs. |
| A navigation runs | A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause, then `head.render()` when it ends | The runtime loads while the next page still loads. |
| No server head applies | `head.load()` right after you create the head | The first entries count as server rendered, so their tags wait for a change. A page with no server render shows no head until then. |

Keep `createHead()` from `@unhead/solid-js/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/solid-js/head/guides/core-concepts/streaming). The lazy head does not support streaming.

## Setup

Replace `createHead()` in the client entry with the one from `@unhead/solid-js/lazy`. Create the head outside `hydrate()`, so the entry can call `head.render()` after it:

```tsx [src/entry-client.tsx]
import { createHead, UnheadContext } from '@unhead/solid-js/lazy'
import { hydrate } from 'solid-js/web'
import App from './App'

const head = createHead()
// Pause head updates while a navigation runs. The pause also holds the load.
let navigating = false
head.hooks.hook('dom:beforeRender', (ctx) => {
  if (navigating)
    ctx.shouldRender = false
})

hydrate(() => (
  <UnheadContext.Provider value={head}>
    <App />
  </UnheadContext.Provider>
), document.getElementById('root')!)
// Hydration has ended.
head.render()

// Call this when your router starts a navigation.
export function startNavigation() {
  navigating = true
}

// Call this after the new page renders, and when the navigation fails.
export function endNavigation() {
  navigating = false
  head.render()
}
```

Solid marks the components that `hydrate()` runs against the server HTML. A push from such a component counts as server rendered. A push from `onMount()`, or from a component that mounts after hydration, cannot be in the server head, so it loads the runtime at once.

The server keeps `createHead()` from `@unhead/solid-js/server`. Nothing changes there.

## What loads the runtime

After hydration, the first head change loads the runtime. The runtime renders the whole head, and it handles every later change. A patch with an equal input is no change.

| Trigger | When the runtime loads |
| --- | --- |
| A signal change that patches an entry with a new value | At once, unless a pause holds it. |
| `useHead()` in `onMount()`, or in a component that mounts after hydration | At once, also before `head.render()`. |
| A dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When it adds its script to the document. |
| `head.load()` | At once. Call it at idle to apply client only values without a change. |

The lazy head compares plain objects, lists, and primitive values. `useHead()` patches its entry with the same input after hydration. A function value, such as `title: () => title()`, counts as a change, so it loads the runtime once hydration ends. To keep the load lazy, pass values and patch from `createEffect()`, as [Reactivity](/docs/solid-js/head/guides/core-concepts/reactivity) shows. Read [What a change does](/docs/vue/head/guides/core-concepts/lazy-head#what-a-change-does) for the full rules. They are the same for every framework.

## Dev warning

In development, the lazy head checks the tags the client would render against the server head after hydration. The console names each tag that waits for the first change. The Solid adapter gives no component name to the lazy head, so the warning names the tag only. Read [Dev warning](/docs/vue/head/guides/core-concepts/lazy-head#dev-warning) for the message and the fix.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| Streaming SSR | The lazy head does not support streaming. | Keep `createHead()` from `@unhead/solid-js/client`. |
| A function value in the input of `useHead()` | It loads the runtime once hydration ends. | Pass values, and patch from `createEffect()`. |
| A `<Show>` or other branch that renders on the client only during hydration | Solid still hydrates the branch, so the head counts its entry as server rendered. Its tags wait for a change. The dev warning names the tag. | Render the same branch on both sides, or show it from `onMount()`. |
| A `<Suspense>` boundary that hydrates after `hydrate()` returns | Its entries arrive after hydration ended, so they load the runtime. | None needed. The page stays correct; the runtime loads early. |
| A value that the client computes differently from the server | The document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, or call `head.load()` after hydration. |
| The runtime chunk fails to load | The document keeps its current head. | Use the `onLoadError` option to recover, for example with a full reload on the next navigation. |
