On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

This guide is for the code that owns the client entry: a custom Vite SSR setup. Components need no change. `useHead()`, `useSeoMeta()`, and `useScript()` work as before.

## What the client entry provides

The lazy head needs three signals that only the client entry has:

| Signal | Call | If the call is missing |
| --- | --- | --- |
| Hydration ended | `head.render()` right after `hydrate()` returns | Every entry counts as server rendered, so a component that mounts after hydration shows no tags until a change. The dev warning never runs. |
| A navigation runs | A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause, then `head.render()` when it ends | The runtime loads while the next page still loads. |
| No server head applies | `head.load()` right after you create the head | The first entries count as server rendered, so their tags wait for a change. A page with no server render shows no head until then. |

Keep `createHead()` from `@unhead/svelte/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/svelte/head/guides/core-concepts/streaming). The lazy head does not support streaming.
- The app follows the [SvelteKit guide](/docs/svelte/head/guides/get-started/sveltekit). There, server load functions push the server tags, and components push other entries on the client. The lazy head expects the client to push what the server rendered.

## Setup

Replace `createHead()` in the client entry with the one from `@unhead/svelte/lazy`:

```ts [src/entry-client.ts]
import { createHead, UnheadContextKey } from '@unhead/svelte/lazy'
import { hydrate, tick } from 'svelte'
import App from './App.svelte'

const head = createHead()
// Pause head updates while a navigation runs. The pause also holds the load.
let navigating = false
head.hooks.hook('dom:beforeRender', (ctx) => {
  if (navigating)
    ctx.shouldRender = false
})

hydrate(App, {
  target: document.getElementById('app')!,
  context: new Map([[UnheadContextKey, head]]),
})
// Hydration has ended. Call it before any `await` or `flushSync()`.
head.render()

// Call this when your router starts a navigation.
export function startNavigation() {
  navigating = true
}

// Call this after you set the new page, and when the navigation fails.
export async function endNavigation() {
  // the new page adds its entries when Svelte renders it
  await tick()
  navigating = false
  head.render()
}
```

Svelte runs component scripts inside `hydrate()`, and runs `onMount()` and `$effect()` after it returns. So call `head.render()` before anything flushes those effects. A push from `onMount()` then loads the runtime, and the first run of an `$effect()` that patches an equal input loads nothing.

The server keeps `createHead()` from `@unhead/svelte/server`. Nothing changes there.

## What loads the runtime

After hydration, the first head change loads the runtime. The runtime renders the whole head, and it handles every later change. A patch with an equal input is no change.

| Trigger | When the runtime loads |
| --- | --- |
| An `$effect()` that patches an entry with a new value | At once, unless a pause holds it. |
| A push from `onMount()`, or from a component that mounts after hydration | At once, unless a pause holds it. |
| A dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When it adds its script to the document. |
| `head.load()` | At once. Call it at idle to apply client only values without a change. |

Pass the initial values to `useHead()`, as [Reactivity](/docs/svelte/head/guides/core-concepts/reactivity) shows. An entry that starts empty and gets its values from an `$effect()` differs from the server head, so it loads the runtime once hydration ends. Read [What a change does](/docs/vue/head/guides/core-concepts/lazy-head#what-a-change-does) for the full rules. They are the same for every framework.

## Dev warning

In development, the lazy head checks the tags the client would render against the server head after hydration. The console names each tag that waits for the first change. Svelte gives no component name to the lazy head, so the warning names the tag only. Read [Dev warning](/docs/vue/head/guides/core-concepts/lazy-head#dev-warning) for the message and the fix.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| Streaming SSR | The lazy head does not support streaming. | Keep `createHead()` from `@unhead/svelte/client`. |
| SvelteKit with the setup of the SvelteKit guide | The server and the client push different entries. | Keep `createHead()` from `@unhead/svelte/client`. |
| A block that renders on the client only during hydration, such as `{#if browser}` | Svelte has no public signal for a component that hydrates. The head counts its entry as server rendered, so its tags wait for a change. The dev warning names the tag. | Render the same block on both sides, or show it from `onMount()`. |
| A value that the client computes differently from the server | The document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, or call `head.load()` after hydration. |
| The runtime chunk fails to load | The document keeps its current head. | Use the `onLoadError` option to recover, for example with a full reload on the next navigation. |
