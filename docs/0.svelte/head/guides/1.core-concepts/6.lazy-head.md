On a server rendered page, the server already wrote the right head tags. The lazy head keeps head entries in memory and leaves those tags alone. The Unhead DOM runtime loads from a separate chunk on the first head change. A visit with no head change never loads it.

::note
The lazy head is experimental. Its options may change in a minor release.
::

This guide sets up the lazy head in a Vite SSR Svelte app, as set up in the [installation guide](/docs/svelte/head/guides/get-started/installation). The same steps fit any setup where your code calls `hydrate()`. Components need no change: `useHead()`, `useSeoMeta()`, and `useScript()` work as before.

Keep `createHead()` from `@unhead/svelte/client` in these cases:

- The app renders on the client only.
- The app uses [streaming SSR](/docs/svelte/head/guides/core-concepts/streaming). The lazy head does not support streaming.
- The app follows the [SvelteKit guide](/docs/svelte/head/guides/get-started/sveltekit). There, server load functions push the server tags. Components push other entries on the client. The lazy head expects the client to push what the server rendered.

## What the client entry provides

The lazy head needs three signals that only the client entry has:

| Signal | Call | If the call is missing |
| --- | --- | --- |
| Hydration ended | `head.render()` right after `hydrate()` returns | Every entry counts as server rendered, so a component that mounts after hydration shows no tags until a change. Every change loads the runtime at once, even during a navigation pause. The dev warning never runs. |
| A navigation runs | A [`dom:beforeRender`](/docs/head/api/hooks/dom-before-render) pause, then `head.render()` when it ends | The runtime loads while the next page still loads. |
| No server head applies | `head.load()` right after you create the head | The first entries count as server rendered, so their tags wait for a change. A page with no server render shows no head until then. |

## Set up the client entry

The server entry keeps `createHead()` from `@unhead/svelte/server`. Nothing changes there.

Create the head from `@unhead/svelte/lazy` in its own module, and add the navigation signal there. Your router imports the navigation functions from this module. A router module also runs on the server, so it must not import the client entry.

```ts [src/head.ts]
import { createHead } from '@unhead/svelte/lazy'
import { tick } from 'svelte'

export const head = createHead()

// Pause head updates while a navigation runs. The pause also holds the load.
let navigating = false
head.hooks.hook('dom:beforeRender', (ctx) => {
  if (navigating)
    ctx.shouldRender = false
})

// Call this when your router starts a navigation.
export function startNavigation() {
  navigating = true
}

// Call this after you set the new page, and when the navigation fails.
export async function endNavigation() {
  // Svelte renders the new page before the tick resolves
  await tick()
  navigating = false
  head.render()
}
```

In the client entry, provide this head instead of the one from `@unhead/svelte/client`. Then add the hydration signal:

```ts [src/entry-client.ts]
import { UnheadContextKey } from '@unhead/svelte/lazy'
import { hydrate } from 'svelte'
import App from './App.svelte'
import { head } from './head'

hydrate(App, {
  target: document.getElementById('app')!,
  context: new Map([[UnheadContextKey, head]]),
})
// Hydration has ended. Call it before any `await` or `flushSync()`.
head.render()
```

Svelte runs component scripts inside `hydrate()`. It runs `onMount()` and `$effect()` after `hydrate()` returns. So call `head.render()` before anything flushes those effects. A push from `onMount()` then loads the runtime. The first run of an `$effect()` that patches an equal input loads nothing.

`endNavigation()` waits for `tick()`. By then, the old page has removed its entries and the new page has added its entries.

To check the result, build the app and load a page with the network panel open. Hydration changes no head element. No Unhead runtime chunk downloads. On the first navigation, the runtime chunk downloads once the new page has rendered. The head then matches what the default client head shows.

## What loads the runtime

After hydration, the first head change loads the runtime. The runtime renders the whole head. It also handles every later change. A patch with an equal input is no change.

| Trigger | When the runtime loads |
| --- | --- |
| An `$effect()` that patches an entry with a new value | At once, unless a pause holds it. |
| A push from `onMount()`, or from a component that mounts after hydration | At once, unless a pause holds it. |
| A dispose during hydration | At once, because the client already differs from the server. |
| `useScript()` | When its script starts to load, even during a pause. With the default trigger, the script starts to load on mount. |
| `head.load()` | At once. Call it at idle to apply client only values without a change. |

Pass the initial values to `useHead()`, as [Reactivity](/docs/svelte/head/guides/core-concepts/reactivity) shows. An entry that starts empty and gets its values from an `$effect()` differs from the server head. So it loads the runtime once hydration ends. Read [What loads the runtime](/docs/vue/head/guides/core-concepts/lazy-head#what-loads-the-runtime) in the Vue guide for the rules that compare input. They are the same for every framework.

## Dev warning

In development, the lazy head checks the tags the client would render against the server head after hydration. The console shows one warning for each tag that waits for the first change. Svelte gives no component name to the lazy head, so the warning names the entry number:

```txt
[unhead] <meta name="rendered-by"> differs from the server head in content. Pushed by entry 1. It applies on the first head change. Push the same input on the server and the client, or call head.load().
```

Read [Dev warning](/docs/vue/head/guides/core-concepts/lazy-head#dev-warning) for what the check compares.

## Known limitations

| Situation | What happens | What to do |
| --- | --- | --- |
| A block that renders on the client only during hydration, such as `{#if typeof window !== 'undefined'}` | Svelte has no public signal for a component that hydrates. The head counts its entry as server rendered, so its tags wait for a change. The dev warning names the tag. | Render the same block on both sides, or show the block from a flag that `onMount()` sets. |
| A value that the client computes differently from the server | The document keeps the server value until the first change. The dev warning names the tag. | Render the same value on both sides, or call `head.load()` after hydration. |
| The runtime chunk fails to load | The document keeps its current head. | Use the `onLoadError` option to recover, for example with a full reload on the next navigation. |
